# Luozi 系统级语音输入体验改造设计

**日期：** 2026-07-28
**状态：** 已确认，待实施计划
**范围：** Mac-first；重构产品入口、HUD、角色反馈、首次引导、设置与历史的信息架构
**不包含：** 本文不直接修改 ASR、文本 AI、跨应用安全交付和云端授权的既有功能逻辑

## 1. 结论

Luozi 不再以「语音草稿工作台」作为产品首页，而是收敛为一个菜单栏优先、系统级原位落字工具：

1. 平时只常驻菜单栏，不自动打开大窗口。
2. 用户在任意可编辑位置按住主快捷键说话，松开后直接写入原输入目标；目标失效时按既有安全规则降级到剪贴板。
3. 录音、处理、成功和失败只通过临时 HUD 反馈，任务结束后自动消失。
4. 语音草稿保留为长文模式，但降为菜单栏中的二级入口，不再与日常落字争夺主心智。
5. 视觉采用「珍珠玻璃 + 呼吸泡 + 轨道声场」；科技感来自明确的信号与状态逻辑，不来自大面积暗色、持续旋转或角色五官变形。
6. 首次引导负责权限、快捷键和真实落字测试；设置、历史和帮助仅按需打开。

目标不是复刻 Typeless 的界面，而是达到同类产品的核心体感：**无需打开主窗口，在当前输入框里自然说、自然落字、失败可恢复。**

## 2. 与既有设计的关系

### 2.1 保留

以下既有能力和安全边界继续有效：

- 本地优先，云端 ASR 和文本 AI 分项配置 Key、分项授权。
- Key 只进入系统钥匙串，不进入配置文件或日志。
- 录音开始时记录输入目标，交付前重新校验；目标变化时不得误投到新焦点。
- 密码框和安全输入区域拒绝录音或丢弃结果。
- 插入失败降级剪贴板；插入成功后使用目标 App 的系统撤销。
- 当前 `Control+Option+Space` 按住说话主链路、`Escape` 取消和现有 M0–M8 能力。
- 工作台的单草稿、自动恢复、撤销、复制和语音修改能力。

### 2.2 更新

本文更新以下产品与视觉决策：

- 更新 `2026-07-25-落字Luozi-快捷录音转文字设计.md` 中以工作台为完整产品中心、以「落光标」为主角的视觉表达。
- 更新 `2026-07-27-guide-window-design.md` 中「不做首次自动引导」的决策：正式产品需要首次引导；菜单内教程仍可保留为后续按需帮助。
- 当前深青色实心 HUD、浅薄荷全窗背景、等权按钮和技术控制台式设置不再作为目标设计。

功能安全规范若与本文视觉描述冲突，以既有安全交付规范为准；本文只改变入口优先级和呈现方式。

## 3. 现状问题

当前 M8 已证明功能主链路可用，但呈现仍像阶段性验证壳：

1. `760 × 600` 工作台以巨大空白编辑器占据首屏，让用户误以为必须先打开 Luozi 才能说话。
2. 草稿、历史、设置、教程并列为产品导航，削弱「任何 App 原位落字」的第一心智。
3. 深青、薄荷和灰色在全窗大面积铺开，层级接近，状态色和品牌色没有明确分工。
4. 设置页直接暴露 ASR、供应商、Key、上传同意等技术结构，普通用户很难判断先做什么。
5. HUD 使用深色实心胶囊和静态 Logo，声音反馈、处理阶段与系统状态缺少统一语义。
6. Key 输入依赖系统脚本对话框，与自定义设置页视觉断裂。
7. 菜单栏图标、App 图标、HUD 角色和设置品牌缺少同一轮廓系统。

改造的首要任务不是增加更多功能，而是让已经存在的能力以正确的产品心智出现。

## 4. 产品结构

### 4.1 常驻与按需入口

| 入口 | 生命周期 | 职责 | 不承担 |
|---|---|---|---|
| 菜单栏 | 常驻 | 就绪状态、开始输入、最近落字、设置、帮助、退出 | 不承载完整技术配置 |
| HUD | 临时 | 聆听、处理、写入结果、错误与恢复动作 | 不展示长文、不常驻 |
| 首次引导 | 首次启动 / 手动重开 | 权限说明、快捷键练习、真实落字测试 | 不讲完整高级功能 |
| 设置 | 按需窗口 | 通用、语音与写作、快捷键、隐私与权限、高级、关于 | 不作为启动首页 |
| 历史 | 按需窗口 | 本地最近记录、搜索、复制、清除 | 不做云同步或知识库 |
| 语音草稿 | 按需窗口 | 长文续写、编辑、语音修改 | 不作为日常落字前置步骤 |

### 4.2 启动行为

- 正常启动后只显示菜单栏图标。
- 默认不弹工作台、不抢焦点。
- 首次启动且引导未完成时打开首次引导。
- 用户关闭设置、历史、引导或草稿窗口时隐藏窗口，App 继续在菜单栏运行。
- Dock 图标策略沿用当前 Mac-first 能力；最终应支持菜单栏工具形态，不要求用户通过 Dock 找主窗口。

### 4.3 菜单栏浮层

菜单栏左键打开约 `300–320 px` 宽的轻量浮层：

1. 顶部：呼吸泡图标、`Luozi 已就绪`、当前本地 / 云端状态。
2. 主动作：`开始语音输入`，同时展示实际注册快捷键。
3. 当前能力摘要：转写引擎、文本整理模式。
4. 次级入口：最近落字、语音草稿、设置、如何使用、退出。

原右键原生菜单可以在迁移期保留；左键浮层稳定后再精简重复入口。

## 5. 核心交互

### 5.1 日常落字

```text
当前输入框有光标
  → 按住 Control+Option+Space
  → HUD 出现，轨道进入聆听态
  → 说话
  → 松开快捷键
  → HUD 进入处理态
  → 校验原输入目标
      → 有效：原位写入
      → 失效 / 不可写：写入剪贴板并明确提示
  → 成功态约 600 ms 后淡出；错误态等待重试或取消
```

### 5.2 快捷键边界

- 正式默认键继续使用已完成 Mac 实机验证的 `Control+Option+Space`（配置串为 `Control+Alt+Space`）。
- 视觉稿中的 `Fn` 仅用于表达「一个主快捷键」的心智，不是当前实现承诺。
- M0 已确认 Tauri 官方全局快捷键能力不能可靠识别独立 `Fn`；首版不得为了模仿竞品引入低级键盘钩子。
- 快捷键录制改键作为后续设置能力；引导和 HUD 必须读取实际已注册值，不能写死示意文案。

### 5.3 草稿与语音修改

- 日常落字只使用主快捷键，不要求先打开草稿。
- 语音草稿从菜单栏按需打开，保留现有长文续写能力。
- 当前语音修改仍以草稿内能力和第二快捷键为主。
- 「选中外部 App 文本后直接语音修改」属于后续阶段，需要独立完成可访问性读取、作用域确认和安全预览，不在本次视觉改造中伪装为已支持。

## 6. 视觉系统

### 6.1 设计性格

关键词：

- 明亮、通透、温暖、克制。
- 有技术质感，但适合长时间使用。
- 静态状态像一件小型玻璃装置；交互发生时才显露声音与计算状态。

避免：

- 大面积深青色实心块。
- 整窗薄荷色滤镜。
- 粗黑描边、霓虹怪兽、通用机器人脸。
- 持续旋转、持续发光、全身抖动。
- 每一行设置都使用同等视觉权重的按钮。

### 6.2 色彩

| Token | 建议值 | 用途 |
|---|---:|---|
| `surface.pearl` | `#FBFDF9` | HUD、菜单浮层和浅色卡片基础 |
| `surface.mist` | `#EEF7F5` | 浅色背景与分组层次 |
| `text.ink` | `#173A3A` | 主文字、图标深色 |
| `brand.mint` | `#62D5C7` | 聆听、轨道节点、主动作 |
| `brand.violet` | `#8B92FF` | 处理中短暂相位 |
| `state.success` | `#50C59F` | 写入成功 |
| `state.error` | `#F1786D` | 单点错误和恢复提示 |

规则：

- 大段正文与标准设置使用系统内容色，不使用品牌色替代可读性。
- 珊瑚色只表达错误或少量情绪，不作为角色常驻嘴部颜色。
- 深色模式使用烟灰玻璃与同一语义色，不简单反转为全屏夜青。
- `降低透明度` 开启时，用实色系统面板和边框保持层级。

### 6.3 字体、间距和形状

- 中文使用苹方，英文使用 SF Pro / 系统 UI 字体。
- 采用 `8 pt` 基础间距；设置行使用桌面密度，不套移动端大按钮。
- HUD 高度目标 `58–64 px`，宽度根据文案约 `360–470 px`，不得遮挡主要正文。
- 菜单浮层约 `300–320 px` 宽。
- 设置窗口沿用当前约 `760 × 560`，但减少全窗色洗和重复标题。
- 圆角分为小控件、标准面板、HUD 胶囊三级；同一层级保持一致。

## 7. 角色与轨道声场

### 7.1 呼吸泡

角色使用一个半透明珍珠气泡：

- 外轮廓稳定、无粗描边。
- 两个小眼睛和一条固定的轻微表情线。
- 角色不随音量缩放，嘴部不随音量张合。
- 静态时无持续动画；允许低频眨眼。
- 菜单栏 `16 px` 图标使用呼吸泡 + 单轨道的单色线稿，不依赖渐变才能识别。

### 7.2 声音与表情解耦

连续声音信号只进入「声音视觉层」：

- 现有 Rust 录音链路从 PCM 样本计算 RMS / 峰值。
- 归一化后做 attack / release 平滑和限幅。
- 以约 `20–30 Hz` 的上限向 HUD 发送能量值，避免每个音频 buffer 都触发前端重绘。
- 能量值只控制轨道段透明度、亮度和可见长度。
- 不控制角色尺寸、五官尺寸和轨道转速。

离散系统事件进入「角色状态层」：

- 开始聆听：轨道亮起。
- 进入处理：轨道切为短暂紫色相位。
- 写入成功：绿色轨道闭合一次，角色轻眯眼。
- 失败：轨道变暗，只亮一个珊瑚节点，角色轻微困惑。

### 7.3 轨道运动约束

- 禁止整圈无限旋转。
- 聆听时轨道段只做约 `±4°` 的低频呼吸或等价的无位移亮度变化。
- 处理中允许一次约 `12°` 的相位移动，完成后停住。
- 成功动作只播放一次，约 `600 ms` 后 HUD 淡出。
- 错误不闪红、不抖动；保持到用户重试或取消。
- `减少动态效果` 开启时，全部改为颜色和透明度离散切换。

## 8. HUD 状态机

| 状态 | 主文案 | 副文案 | 色彩 | 退出条件 |
|---|---|---|---|---|
| `listening` | 正在听你说 | 显示实际快捷键与结束方式 | 薄荷青 | 松开快捷键 / Esc |
| `processing` | 正在整理表达 | 已停止录音，正在准备写入 | 紫色 | 成功 / 失败 / Esc |
| `success-inserted` | 已写入当前输入框 | 可在当前 App 中撤回 | 绿色 | 约 600 ms 自动消失 |
| `success-clipboard` | 已放入剪贴板 | 原输入目标已变化，请粘贴 | 绿色 | 约 2–5 s 或用户关闭 |
| `error-retryable` | 这段没有听清 | 原输入未改变，可以重试 | 珊瑚节点 | 重试 / Esc |
| `error-permission` | 需要开启辅助功能 | 说明用途并提供设置入口 | 琥珀 / 珊瑚 | 打开设置 / 取消 |

HUD 必须继续携带 `sessionId`，晚到结果不得覆盖新会话。

## 9. 首次引导与帮助

### 9.1 三步首次引导

1. **权限**：麦克风和辅助功能分开解释，明确「为什么需要、何时使用、数据去哪里」。
2. **快捷键**：展示当前实际注册键，完成一次按住 / 松开练习。
3. **试说一句**：把光标放进测试框，完成一次真实录音、转写和写入；成功后才标记引导完成。

未配置文本 AI 不阻止完成引导；本地模型不可用时应明确给出下载或已授权云端的可用路径。

### 9.2 按需帮助

现有教程窗方案可以改为「如何使用」入口：

- 复用首次引导内容与说明组件，避免维护两套文案。
- 帮助模式不重置完成状态。
- 快捷键从配置动态读取。
- 高级 ASR、Key 和供应商说明跳转到设置对应页，不在帮助首屏堆叠。

## 10. 设置与历史

### 10.1 设置结构

左侧只保留六组：

1. 通用
2. 语音与写作
3. 快捷键
4. 隐私与权限
5. 高级
6. 关于

通用页只放：

- 登录时启动。
- 关闭窗口时继续运行。
- 默认输入方式。
- 跟随系统外观。
- 是否保留本地历史。

语音与写作页用产品语言说明：

- 转写质量与速度偏好。
- 本地优先 / 云端优先的可理解选择。
- 基础整理、文本 AI 润色的启用边界。

提供方、Base URL、模型名、Key、分项上传同意和诊断信息全部进入「高级」，并按 ASR / 文本 AI 分组，禁止重复等权按钮。

### 10.2 历史

- 默认本地保存，最多 50 条，允许关闭。
- 提供搜索、复制、删除单条、清空全部。
- 单条显示时间、应用来源和结果摘要；不保存外部输入框原文。
- 历史不是启动首页，不增加云同步、标签和文档库。

## 11. 组件与职责边界

| 单元 | 职责 | 依赖 |
|---|---|---|
| `VoiceEnergyMeter` | 从 PCM 计算并平滑能量值 | 现有录音样本 |
| `HudStateModel` | 将会话阶段映射为稳定 UI 状态 | session controller |
| `OrbitAvatar` | 渲染呼吸泡、轨道和一次性状态动作 | energy + HUD state |
| `OverlayWindow` | 定位、显示、隐藏临时 HUD | Tauri window |
| `TrayPopover` | 菜单栏轻量入口和状态摘要 | settings / engine status |
| `OnboardingFlow` | 权限、快捷键、真实落字测试 | permissions / session |
| `SettingsShell` | 普通设置与高级配置分层 | settings API |
| `HistoryStore` | 本地 50 条记录及清理 | local storage |

边界要求：

- `OrbitAvatar` 不读取录音 buffer，只接收归一化能量和离散状态。
- `TrayPopover` 不直接操作钥匙串；配置动作通过现有命令接口。
- `OnboardingFlow` 不复制权限判断逻辑，复用正式权限 API。
- 设置视觉重构不改变云端授权和 Key 存储语义。

## 12. 错误与降级

- 麦克风拒绝：HUD 明确说明未录音，提供系统设置入口。
- 辅助功能未生效：允许转写，但结果走剪贴板并解释原因。
- 本地模型缺失：显示下载入口；未授权云端时不得静默上传。
- 网络或云端失败：若本地可用则按既有路由回退，否则保留原输入并提供重试。
- 输入目标变化：不抢回旧应用，不向新焦点插入，走剪贴板。
- HUD 前端异常：会话控制器必须能够超时收口并隐藏 overlay。
- 降低透明度 / 无 GPU 材质：切换为不透明系统面板，不影响状态可读性。

## 14. 验收标准

### 产品结构

1. 正常启动不自动打开工作台；菜单栏可确认 Luozi 已就绪。
2. 日常落字无需打开任何 Luozi 窗口。
3. 草稿、设置、历史、帮助均为按需入口。
4. 普通设置首屏不直接出现供应商、Key 和上传授权按钮。

### HUD 与角色

5. 四个核心状态在浅色和深色背景上可区分。
6. 音量变化不改变角色或五官尺寸，不改变轨道转速。
7. 空闲无持续动画；`减少动态效果` 下无旋转和位移动画。
8. 成功写入后 HUD 按设计自动淡出；错误态不会自动消失到用户无法判断。
9. `16 px` 菜单栏单色图标仍能识别为呼吸泡 + 轨道。

### 引导与设置

10. 首次引导完成麦克风、辅助功能和一次真实落字测试。
11. 权限说明回答用途、时机和数据去向。
12. 引导和 HUD 展示实际注册快捷键，不写死 `Fn`。
13. 高级设置仍能完成现有 ASR / 文本 AI Key 与分项授权。

### 安全与性能

14. 输入目标切换、密码框、辅助功能失败和晚到结果继续遵守既有安全规则。
15. 关闭窗口后无 UI 计时器持续运行；录音结束后停止能量事件。
16. 能量事件限频，不因 PCM buffer 频率导致 Webview 高频重绘。
17. 既有本地 Whisper、云端路由、草稿和语音修改功能不回归。

## 16. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 视觉升级演变成全量重写 | 改动范围失控，现有主链路回归 | 按 R1–R3 分阶段，先复用现有窗口和 API |
| 轨道动效消耗 GPU | 常驻耗电、窗口掉帧 | 空闲静止、能量限频、只在 HUD 可见时渲染 |
| 首次引导与教程重复 | 两套权限和快捷键文案漂移 | 共用内容模型和动态配置 |
| `Fn` 竞品心智诱导错误实现 | 引入低级钩子、破坏签名与稳定性 | 首版坚持已验证快捷键，改键另立任务 |
| 左键菜单浮层跨平台定位差异 | 贴不准菜单栏 / 托盘 | Mac-first 先做；保留右键原生菜单降级 |
| 设置重排破坏授权边界 | ASR / 文本 AI 同意被混淆 | 只改信息架构，保留现有分项 API 与状态 |
| 当前工作树已有大量改动 | 视觉实现与未完成功能混在一起 | 实施前确认基线，按阶段提交，不重写无关模块 |

## 17. 明确非目标

- 不模仿 Typeless 的品牌、文案或角色。
- 不为单独 `Fn` 引入低级键盘钩子。
- 不用音量控制嘴巴大小、眼睛大小或角色缩放。
- 不做持续整圈旋转、持续粒子雨或常驻背景动画。
- 不把语音草稿删除；只调整入口优先级。
- 不在本次视觉改造中重写 ASR、云端供应商、钥匙串和跨应用交付。
- 不把历史扩展成账号、云同步、多文档或知识库。
