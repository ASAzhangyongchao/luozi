# 落字（Luozi）快捷录音转文字 — 完整产品设计

## 结论

做独立开源桌面应用 **落字（Luozi）**：

- **平台**：macOS + Windows 双端同版本能力对齐（系统能力差异用「平台适配层」消化，产品功能不因平台阉割主路径）。
- **分发**：独立公开 GitHub 仓库 + Releases 提供可下载安装包（Mac / Windows）。
- **能力**：全局快捷键录音（有无输入焦点均可）→ 转写 → 保守整理成可读文字 → 安全校验原输入目标后插入，否则自动进剪贴板；同一个 App 内提供按需打开的「语音草稿工作台」，支持语音续写、语音修改、转写纠错、AI 润色和粘贴文字美化。
- **交互**：只保留两个核心动作——「继续说」和「说出修改要求」；不把纠错、润色、改写拆成一排模式卡片，点击入口只作快捷键和语音操作的备用。
- **默认策略**：本地优先；只有用户明确配置并授权某个云端提供方后，音频才允许离开本机；双路竞速默认关闭。
- **AI 交付**：首版不建账号、不提供落字官方云服务、不捆绑本地大语言模型；本地转写与基础整理可直接使用，深度润色和自然语言修改由用户第一次使用时配置自己的兼容 API 或本机服务。
- **轻量策略**：托盘常驻层不加载编辑器、ASR 模型和文本 AI；工作台、模型与动画均按需启停，文本 AI 不做后台持续扫描。
- **品牌**：原创命名、Logo、视觉与文案；只参考「全局语音输入」品类能力，不仿制竞品。

实现真相源为独立公开仓 `luozi`；本知识库通过 `apps/luozi/` submodule 固定公开仓提交，模式对齐 QuotaPet，不维护双向复制目录。

本文件按「可直接拆实现计划、可直接创建公开仓骨架」维护：产品承诺、接口边界、平台差异、失败处理和验收标准必须能落成任务，不能只停留在效果描述。

## 0. 与 QuotaPet 对齐的开源交付原则

落字与 QuotaPet 同属「个人开源桌面工具」线，**开源与发版原则共用**；产品能力与技术栈各自独立。

| 原则 | 落字 | QuotaPet（现状 / 方向） |
|---|---|---|
| 公开 GitHub 源码 | 独立公开仓 `luozi` | 已有 `quota-pet` |
| Releases 可下载 | **必须**挂安装包，禁止长期只发空 tag | 已有 ad-hoc DMG/ZIP 规则 |
| macOS | MVP 必交付 | 已交付 |
| Windows | **MVP 必交付**（与 Mac 同里程碑目标） | 公开路线图：二期/另开技术选型，不在本仓库用 Swift 硬撑 |
| LICENSE | MIT | 随公开仓 |
| 证书 | Mac 先 ad-hoc；Windows 先未签名/自签名说明 SmartScreen | 同：先 ad-hoc，个人 Developer 再升级公证 |
| 隐私 | 无私服账号；Key 只存本机；不塞分析 SDK | 同精神 |

**共同发版清单（每次用户可感知变更收口时）**：

1. 升版本号（SemVer）+ 更新 `CHANGELOG`（中英至少一种完整，推荐双语）。
2. CI 或本机脚本产出双端包，上传到 **同一 Release**。
3. Release 正文写清：支持系统版本、是否签名/公证、已知限制、SHA256。
4. README「Download」区链到最新 Release；截图与特性与当前版本一致。
5. 源码与安装包同源：tag = 构建提交；附件校验和进 Release notes 或 `SHA256SUMS`。

## 1. 产品定位与成功标准

**一句话**：对着任何输入框说话，字马上落下来。

| 验收项 | 标准 |
|---|---|
| 双端可用 | 同一大版本下，Mac / Windows 均可完成：热键录音 → 转写 → 插入或剪贴板回退 |
| 体感速度 | 短句（≤5 秒语音）结束录音到插入，目标 ≤1.5s（本机小模型或已配好的低延迟云端） |
| 不抢焦点 | 录音与转写不把用户从原应用拽走 |
| 不误投 | 录音后切换应用、窗口或输入框时，**不得**把结果插入新焦点；目标失效统一降级剪贴板 |
| 引擎可配 | 本地可检测/下载/自选；云端可配 Base URL + Key + 模型；优先提供低门槛且文档稳定的厂商预设 |
| 隐私可预期 | 默认不上传；首次启用每个云端提供方时明确展示目标域名、上传内容和提供方数据政策 |
| 中文准确率 | 固定 50 条个人常用短句基线集；安静环境下，推荐本地模型与默认云端预设分别记录规范化 CER，公开 `v0.1.0` 目标 ≤12% |
| 落点可靠性 | 兼容性测试矩阵中，插入成功或明确降级剪贴板的总成功率 ≥99%；密码框误插入为 0 |
| 性能口径 | 5 秒短句分别记录冷启动 / 热启动的 P50、P95；“≤1.5s”只承诺热模型或已配置低延迟云端的 P50 |
| 成文质量 | 快捷落字至少完成标点、明显口头重复和段落整理；任何可能改变数字、专有名词或原意的处理必须保守或标记待确认 |
| 工作台闭环 | 一个文稿内可完成：语音续写、粘贴、纠错、润色、按语音要求修改、撤销和复制；不要求切换页面或进入聊天窗口 |
| 语音修改可控 | 有选区时只改选区；无选区时默认改当前段；涉及全文、大比例删除、数字或专有名词变化时必须预览或语音确认 |
| 首次可用 | 新用户不配置文本 AI 也能完成本地录音、转写、基础整理、插入 / 剪贴板与工作台编辑；第一次使用深度 AI 时再一次性配置 |
| 轻量常驻 | 基线机器上，后台空闲 5 分钟后 CPU P95 ≤0.5%、应用私有常驻内存目标 ≤120 MiB、无持续 GPU 占用；模型内存单独统计 |
| 开源可装 | GitHub 能下到对应平台安装包，按 README 能跑通首次引导 |
| 原创合规 | 视觉与文案不构成竞品换皮；第三方组件按许可证致谢 |
| 密钥安全 | Key 只进系统凭据库；不进 git、日志、崩溃上报 |

首个公开版支持基线：

- macOS 13+，优先交付 Apple Silicon；Intel 包在 CI 能稳定产出后再纳入正式承诺。
- Windows 10 22H2 / Windows 11，x64。
- 简体中文与英文界面；识别语言默认自动，允许显式选 `zh` / `en`。

## 2. 已拍板决策

| 决策 | 结论 |
|---|---|
| 平台 | **macOS + Windows**（Linux 不进 MVP，可作社区贡献项） |
| 技术形态 | **跨平台壳 + 共享核心**（推荐 Tauri 2 + Rust 核心；UI 使用平台系统材质与落字品牌语义，不套默认模板） |
| 引擎 | 本地 + 云端都要；默认「自动（本地优先）」；云端需逐提供方授权；竞速预留为二期高级选项 |
| 第一目标 | 快 |
| 录音手势 | 按住松手 + 按一下开关；**默认按住** |
| 语音修改 | 第二快捷键进入「修改指令」录音；工作台内按选区 → 当前段 → 明确全文的顺序确定作用范围 |
| 草稿形态 | 与快捷落字同一 App；单窗口、单活动草稿、无文档库、无聊天历史 |
| AI 成文 | 快捷落字只做保守整理；工作台内按用户明确指令做纠错、润色和改写；失败不阻断原始转写 |
| AI 服务 | **BYOK / 自备本机服务**；无落字账号、无官方中转服务、无内置共享 Key |
| 品牌 | 落字 / Luozi；「落光标」Logo；「落光 · Falling Cursor」专属 UI；夜青 + 极光青为品牌色，琥珀 / 红 / 电光蓝只表达明确状态 |
| 分发 | GitHub 开源 + Releases 双端安装包 |
| 目录 | `apps/luozi/` |
| 标识 | macOS Bundle ID `app.luozi.desktop`；Windows AppUserModelID / 安装名 `Luozi` |

> 原「仅 macOS 原生 Swift」方案废止：无法干净交付 Windows。Swift 经验（热键、悬浮层）只作交互参考，不绑死实现语言。

## 3. 产品边界

### 3.1 MVP 做

- 双端：系统托盘 / 菜单栏常驻
- 全局快捷键录音（按住 / 开关）
- 原创、平台自适应的液态玻璃悬浮录音条
- 有焦点则插入；无焦点也可热键，转写后**自动进剪贴板**（见 §5.3 / §5.4）
- 本地主引擎：内嵌 `whisper.cpp` 兼容运行时 + 固定支持的 GGML 模型格式；自带检测、一键下载、哈希校验和分平台教程

- 云端：通用 OpenAI 兼容转写 + 明确的厂商适配器 + 自定义；启用前显式授权
- 单文稿「语音草稿工作台」：语音续写、正常换行、粘贴文字、复制、崩溃恢复
- 第二快捷键 / 同一语音控件进入修改指令：纠错、通顺、缩写、扩写、调整语气、按要求重组
- 当前草稿为空时，可把落字自己产生的最近一次转写载入工作台后继续修改；不读取外部 App 正文
- 疑似错误与 AI 改动标注、键盘 / 语音撤销；复制与导出不携带颜色标记
- 文本 AI 提供方与 ASR 引擎分离；首版使用用户配置的云端或本机兼容服务，不捆绑常驻大语言模型
- 最小完整设置 + 首次三步引导
- 公开仓 README / LICENSE / CI 骨架 / Release 脚本

### 3.2 MVP 不做

- 账号 / 订阅 / 云同步历史
- 落字官方 AI 中转服务、公共 API Key、免费额度运营
- 实时字幕流式上屏（可留协议）
- 多语言互译模式
- 会议纪要、模板库、团队管理
- 多文档管理、云同步、富文本排版、聊天式 AI 侧栏
- 自动读取或改写其它 App 的选中文字（首版只保证工作台内的可控修改）
- iOS / Android / Linux 官方包
- 双路竞速功能
- Ollama ASR、Apple Speech、Windows Speech 作为正式主路径
- 内置本地大语言模型、后台持续语法检查、全文语义索引
- 复杂剪贴板（图片、文件、多格式对象）的完整撤销
- 商店上架（Mac App Store / Microsoft Store）——可作后续渠道，不挡 GitHub 发版

### 3.3 二期候选

- 流式预览、个人词库、多草稿 / 本地历史、跨 App 选中文字后语音改写、Ollama / 系统语音实验适配器、可选本地文本模型、双路竞速、更多预设、Linux、商店签名升级、自动更新（Sparkle / Win 等价）

## 4. 品牌与视觉（原创约束）

### 4.1 品牌气质

落字的第一感受定为：**轻盈、智能、未来，但安静、克制、适合长期写作**。它不是聊天机器人、会议工具或炫技型录音器，而是把声音自然送进光标位置的桌面输入工具。

专属视觉语言命名为 **「落光 · Falling Cursor」**：声音像一道轻光落进正文，操作层有短暂的系统玻璃质感，内容层始终稳定、清楚。

| 项 | 定稿 |
|---|---|
| 中文名 | 落字 |
| 英文名 | Luozi |
| 品牌方向 | 轻盈、智能、未来；避免厚重文学风、游戏霓虹感和通用录音软件感 |
| Logo | 「落光标」：声音光标凝成字点并落到输入基线；托盘 / 菜单栏使用单色线稿 |
| UI 风格 | 「落光 · Falling Cursor」；内容稳定，控制与短反馈使用系统玻璃 |
| 主色 | 夜青 `#0B3034` + 极光青 `#42D9D3`；系统内容色承担大段正文 |
| 录音条 | 平台原生材质的圆角玻璃胶囊；常态收起，录音时扩展为状态 + 波形 + 取消，不堆额外操作 |
| 动效 | 玻璃控件只在「待机 → 录音 → 转写 → 完成」间短暂形变；减少动态效果时改为无位移淡变 |
| 文案 | 短、动词明确；禁止复用竞品提示句 |
| 双端一致 | 同一套层级、间距与语义色；macOS 使用系统 Liquid Glass / vibrancy，Windows 使用 Mica / Acrylic 等系统材质，不用一套伪 iOS CSS 强盖两个平台 |

### 4.2 Logo 系统：落光标

核心图形只由四种几何关系组成：

1. 中间是一根圆润的竖向光标，代表文字正在生成的位置。
2. 光标底部断开一小段并凝成「字点」，表达声音变成文字后落下。
3. 字点下方是一条较短的输入基线，不画完整文稿或键盘。
4. 左右各保留一条不对称短回声弧，表达声音；不使用常见的多柱均衡器、完整麦克风或聊天气泡。

不同载体采用同一骨架：

| 载体 | 规则 |
|---|---|
| App 图标 | 平台系统圆角容器；夜青底，冰白光标，极光青字点；只允许很轻的材质层次，不做复杂 3D、厚投影和多层玻璃 |
| 菜单栏 / 托盘 | 单色线稿；只保留光标、字点、输入基线和两条短回声弧；在 16 px 下仍可辨认 |
| 品牌组合 | 中文「落字」为主，英文 `LUOZI` 字距略放宽为辅；不使用衬线字体制造文学感 |
| 单色与高对比 | 必须提供纯黑、纯白和高对比版本；去掉渐变与发光后仍保持识别 |
| 动效版本 | 录音时回声弧轻微呼吸；松开后字点下移约 4 px；完成时只亮一次；空闲时完全静止 |

品牌资产必须有可编辑矢量真相源，建议公开仓最终使用：

```text
assets/brand/
  luozi-mark.svg
  luozi-wordmark-zh.svg
  luozi-wordmark-en.svg
  luozi-tray-template.svg
  app-icon-source.svg
```

- 各尺寸 PNG、ICNS、ICO 和 Windows Store 图标从同一矢量源生成，不手工维护多套形状。
- 当前 M1 仓库中的 `assets/luozi-icon-source.png` 与已生成图标属于**临时实现资产**，不得视为最终品牌真相源；公开展示前由「落光标」矢量资产替换。
- Logo 不嵌入细小文字，不依赖发光、透明或渐变才能识别。

### 4.3 色彩与状态

| Token | 色值 | 用途 |
|---|---|---|
| 夜青 `Night Teal` | `#0B3034` | 品牌底色、深色模式控制面，不作为大段正文背景硬铺全窗 |
| 极光青 `Aurora Cyan` | `#42D9D3` | 主动作、录音、成功流转；浅色模式下不直接作为小号正文文字 |
| 冰白 `Ice White` | `#F4FBFA` | 深色控制面上的图形与文字 |
| 电光蓝 `Electric Blue` | `#6C8EFF` | 本次 AI 修改的短暂标记，不作为第二套品牌主色 |
| 琥珀 `Amber` | `#E8A54B` | 疑似错字、需要确认 |
| 风险红 `Risk Red` | `#E06161` | 数字、姓名、日期、项目名冲突及阻断错误 |

- 正文与大面积背景优先使用系统内容色、窗口色和可访问性语义色，不把品牌色铺满编辑区。
- 极光青表达「正在执行 / 可以继续」，琥珀表达「请确认」，红色只表达高风险或失败；不能为了装饰随意混用。
- 深浅色模式都必须满足正文、按钮和标记的可读性；增强对比度时移除半透明边缘并加实线轮廓。

### 4.4 字体、图标与空间

- 中文界面使用平台系统无衬线字体：macOS 优先苹方，Windows 优先微软雅黑 / Segoe UI 回退；英文使用系统 UI 字体。
- 正文不使用品牌字体，保持系统编辑体验；品牌字只在图标、关于页和空状态少量出现。
- 功能图标优先使用 SF Symbols / Windows 系统等价图标，并通过语义映射保持一致，不混入多套线性图标库。
- 基础间距采用 8 pt 网格；正文区保持宽松行距，工具栏和设置保持桌面密度，不套移动端的大号触控卡片。
- 圆角形成三级：小控件、标准浮层、录音胶囊；同一容器内保持同心圆角，不随意给每张卡片不同半径。

### 4.5 「落光」界面层级

界面只保留三层：

1. **内容层**：正文编辑器、设置列表和长说明。高可读、稳定，不铺玻璃、不使用持续渐变。
2. **控制层**：顶部工具栏、底部语音控件、托盘迷你面板和确认浮层。优先使用平台标准控件与系统玻璃。
3. **状态层**：疑似词、风险项、AI 改动和短反馈。只在需要时出现，不常驻抢占注意力。

视觉原则：

1. **内容在前，玻璃在后**：正文编辑区保持高可读的标准内容材质；液态玻璃只用于工具栏、语音控件、浮层和短反馈。
2. **系统控件优先**：窗口、菜单、设置、按钮和辅助功能尽量使用平台标准实现，避免自制厚重边框、渐变卡片和常驻装饰。
3. **一屏一个主动作**：快捷录音态只突出「继续说」；工作台只突出底部语音控件。复制、导出、设置收进标准工具栏或菜单。
4. **颜色表达状态**：极光青表示录音与主动作，琥珀表示不确定，红色表示数字 / 名称 / 时间等高风险，电光蓝仅短暂表示 AI 改动。
5. **适配辅助功能**：跟随深浅色、降低透明度、增强对比度和减少动态效果；关闭透明后仍能清楚区分内容层与操作层。
6. **空闲即静止**：没有录音、转写或修改任务时，不运行波形、光点、折射和计时动画；视觉效果不能破坏轻量常驻目标。

### 4.6 视觉验收

- Logo 在 `16 / 32 / 128 / 1024 px`、纯黑白、浅色 / 深色系统背景上都能辨认，16 px 不糊成普通声波。
- App 图标、菜单栏 / 托盘图标、悬浮条状态图形使用同一「落光标」骨架，不各画一套。
- 工作台首屏只出现一个主动作；没有功能宫格、聊天气泡、永久 AI 侧栏和连续装饰动画。
- 正文区域在浅色、深色、降低透明度和增强对比度下均保持稳定可读。
- 录音条和工作台空闲 30 秒后无持续动画、无持续 GPU 占用；关闭工作台后不保留 UI 计时器。
- 与语音输入、听写和 AI 写作品类的常见 Logo 做轮廓对比；若仅看剪影容易误认为其它产品，则继续收敛，不以换颜色作为原创证明。

## 5. 核心交互（双端同一套语义）

### 5.0 先澄清两个易混概念

| 说法 | 本文含义 |
|---|---|
| 有没有「选中输入框」 | 指系统里是否存在**可编辑输入焦点**（光标在文本框里），不是「有没有用鼠标拖选中一段字」 |
| 有焦点且拖选了文字 | 写入时按系统惯例：**替换当前选区**（和正常打字/粘贴一样） |
| 无焦点 | 桌面、浏览器非输入区、纯只读界面等 → **不假装插入**，走剪贴板主路径 |

**拍板（回答你的两个问题）**：

1. **说错了怎么取消？** → 分阶段，见 §5.4；核心是「录音/转写中可作废；已经写出去后用撤销恢复剪贴板（无焦点）或靠目标 App 的撤销（有焦点插入）」。
2. **说对了但没点输入框？** → **自动写入剪贴板**（不用再点「复制」）；同时弹出短反馈展示原文，让用户知道「已经在剪贴板上了」。反馈不是「先提示再让你点复制」。

### 5.1 主快捷键：继续说（**不要求先点输入框**）

1. 任意界面按住快捷键 → 悬浮条出现并录音（有无焦点都可以）
2. 松手 →「落字中…」→ 转写
3. 快捷输入先完成标点、分句、显然口头重复和低风险错字的保守整理；文本 AI 不可用或超时则直接使用原始转写，不阻断落字
4. 按 §5.3 **落点路由**交付结果；工作台位于前台时，结果插入光标处并保留自然段结构
5. 失败：条变红 +「重试」；已有文本时提供「复制」（兜底，非常规主路径）

### 5.2 开关模式

按一下开始，再按一下结束（或点「落」）。设置里显式二选一，默认按住。同样**不要求先有输入焦点**。

### 5.3 落点路由（有焦点 vs 无焦点）

转写成功后的唯一决策树：

```text
按下热键：记录 sourceTarget（应用 / 窗口 / 可编辑元素身份，不读取内容）
        │
转写成功得到 text
        │
        ├─ sourceTarget 仍存在、仍可编辑，且前台应用 / 窗口未改变？
        │     是 →【插入路径】写入原目标（有选区则按目标应用当前选区规则替换）
        │           · 默认不改剪贴板（避免悄悄覆盖用户正在用的复制内容）
        │           · 反馈：「已落字」+ 可展开预览；约 2s 后淡出
        │           · 若插入失败 → 降级为【剪贴板路径】
        │
        └─ 否（无焦点 / 目标变化 / 焦点不可写）
              →【剪贴板路径】自动写入系统剪贴板（主路径，零次额外点击）
                    · 仅当上一份剪贴板是普通文本且大小合规时，保存文本快照供撤销
                    · 反馈条必现：「已落到剪贴板」+ 全文/首行预览
                    · 反馈条按钮：撤销 | 再复制（一般用不到）
                    · 用户之后在目标处自行粘贴（⌘V / Ctrl+V）
```

#### 5.3.1 输入目标安全规则

1. 热键开始录音时捕获 `sourceTarget`；只保存进程、窗口和可编辑元素的短期身份信息，不读取或记录目标输入框正文。
2. 交付前再次校验目标。用户只要切换了前台应用、窗口或输入元素，就不激活旧窗口、不写入新窗口，统一走剪贴板。
3. `sourceTarget` 失效、目标应用拒绝辅助功能写入或写入结果不可确认时，统一走剪贴板。
4. 如果开始录音时识别到密码框、安全输入区域或系统认证弹窗，直接拒绝启动录音；如果只能在交付时识别出来，则丢弃结果，不插入、不写剪贴板、不展示全文。
5. 插入操作必须带当前 `sessionId`；被取消或已过期会话即使晚到结果，也只能丢弃，不能落字。

| 场景 | 系统做什么 | 用户要做什么 |
|---|---|---|
| 已点进输入框且说对了 | 直接插入 | 无（可继续打字） |
| 没点输入框且说对了 | **自动进剪贴板** + 提示「已落到剪贴板」 | 去目标处粘贴 |
| 没点输入框且说错了 | 见 §5.4：录音中取消；或已复制后点「撤销」 | 取消或撤销后重录 |
| 插入失败 | 自动改走剪贴板路径 + 说明原因 | 粘贴 |
| 转写期间切了应用 / 窗口 / 输入框 | 不向新目标插入，自动进剪贴板 | 在需要的位置粘贴 |
| 密码框 / 安全输入 | 不录音；晚识别时丢弃结果 | 离开安全输入区域后再使用 |

设置项（通用页）：

| 项 | 默认 | 说明 |
|---|---|---|
| 无焦点时自动写入剪贴板 | **开（且建议锁定为产品默认行为）** | 关掉则无焦点时只出预览条，需点「落入剪贴板」——与「少一步」目标冲突，仅作高级项 |
| 有焦点插入成功时也同步剪贴板 | **关** | 开了会多覆盖一次剪贴板；需要「插入顺便带走一份」的人再开 |
| 剪贴板结果反馈条时长 | 5s | 超时淡出；撤销入口仍留在托盘「撤销上次落字」一段时间（如 60s） |

### 5.4 取消与说错了（分阶段，避免乱）

把「取消」拆成三条时间线，用户心智只需记：**录的时候 Esc；已经落出去用撤销**。

| 阶段 | 用户动作 | 系统行为 | 剪贴板 | 输入框 |
|---|---|---|---|---|
| A. 录音中（条还在听） | `Esc` 或点「收」 | 丢弃音频，不转写 | **不动** | 不动 |
| B. 转写中（落字中…） | `Esc` | 尽量 abort 请求；当作取消 | **不动** | 不动 |
| C1. 已走剪贴板路径（无焦点说完了） | 反馈条「撤销」或托盘「撤销上次落字」 | 条件满足时恢复上一份普通文本；清掉「上次落字」缓存 | 有条件恢复 | — |
| C2. 已走插入路径（有焦点说完了） | 目标应用内 `⌘Z` / `Ctrl+Z` | 落字**不保证**能跨进程撤销插入；反馈条可提示「可在当前应用里撤销」 | 默认未改 | 由目标 App 撤销 |
| C3. 说错但想重来 | 再按一次快捷键重录 | 新结果按路由覆盖；剪贴板路径会再次快照 | 新文本覆盖 | 新插入或再粘贴 |

补充规则：

- **误触极短录音**（&lt;0.3s）：直接丢弃，等同取消，不弹失败恐吓。
- **撤销只有限保证普通文本剪贴板**：图片、文件、多格式对象和超大文本不承诺完整恢复。
- **有条件恢复**：仅当当前剪贴板仍是本次落字写入的文本、且序列号未被其它应用改变时才允许恢复；用户已经复制新内容时，撤销不得再次覆盖。
- **快照上限**：上一份普通文本最大保存 1 MiB，只驻留内存，退出应用或超过 60 秒即清除。
- **插入路径不靠落字 App 强行删字**：跨应用删字符不可靠，避免搞出半截字；文案引导用系统撤销。
- 托盘右键增加：`撤销上次落字`（仅当存在可撤销的剪贴板快照时可点）。

### 5.5 结果反馈条（无焦点时的「确定感」）

无焦点自动复制后，用户容易怀疑「到底有没有成功」。因此反馈条是**成功确认**，不是复制按钮：

```
┌──────────────────────────────────────────────┐
│ 已落到剪贴板 · 去目标处粘贴即可                 │
│ 「今天下午三点开会」                     撤销  │
└──────────────────────────────────────────────┘
```

- 主文案明确「已经在剪贴板上」
- 展示转写原文（过长省略，可点开）
- **不**做成「请点击复制」主按钮
- 「再复制」放次级，仅当用户又覆盖了剪贴板后想取回本次结果

有焦点插入成功时反馈更轻：`已落字`（可带短预览），不强调剪贴板。

### 5.6 平台快捷键策略（可改）

**动作语义现在定稿，具体默认组合键由 M0 实机 Spike 定稿。** 不在验证前把某组看似顺手的组合写成产品承诺：系统、输入法、辅助功能和常用软件都可能占用全局键，单纯“注册成功”也不等于能稳定收到按下 / 松开。

默认键选择规则：

1. Mac / Windows 分别维护一组候选，M0 在两端验证系统保留键、中文输入法、Word、浏览器和 VS Code；通过后把第一组写入公开仓默认配置。
2. 首次启动先静默尝试注册默认键，并在练习框要求用户真实按住、松开各一次；只有冲突或收不到完整事件时，才出现一次简短的「按下你想使用的快捷键」。
3. 修改后的快捷键立即试注册并保存；注册失败不覆盖旧值。重启后自动复核，失效时托盘显示单点提醒，不弹连续窗口。
4. 支持每个动作一组主绑定；多套备用绑定放二期，避免热键监听面过大。`Esc` 固定用于取消当前落字任务，不允许改成普通输入键。
5. macOS 不采用系统已占用的 `⌥⌘Space`。若 M0 证明 `Fn` 能用窄平台适配稳定收到按下 / 松开且权限成本可接受，可优先作为「继续说」；否则使用通过实机矩阵的组合键。

两个快捷键的职责固定，不依赖模型猜测用户意图：

- **继续说**：在外部 App 中执行快捷落字；在工作台中从当前光标继续写。
- **语音修改**：工作台已打开时直接录制修改要求；工作台未打开时先打开当前草稿，再进入修改指令。
- 工作台没有内容时触发「语音修改」：若内存中有落字自己产生且仍在有效期内的最近一次结果，先载入并提示「已载入上次落字」，再录制修改要求；否则提示「先说一段或粘贴文字」，不把修改指令误当正文。
- MVP 不在后台读取其它 App 的选区或正文；外部文字通过用户主动复制 / 粘贴进入工作台后再修改。

右键「开始/停止语音输入」始终为开关语义，与按住快捷键并存。

### 5.7 会话状态机与并发

```text
Idle
  └─ start ─► Recording
                ├─ cancel / too-short ─► Canceled ─► Idle
                └─ stop ─► Transcribing
                              ├─ cancel / late-result ─► Canceled ─► Idle
                              ├─ fail ─► Error ─► Idle
                              └─ success ─► Delivering
                                               ├─ inserted ─► Success ─► Idle
                                               ├─ clipboard ─► Success ─► Idle
                                               └─ fail ─► Error ─► Idle
```

- MVP 同时只允许一个活动会话；`Transcribing` / `Delivering` 时再次触发热键，不创建第二条任务，提示「上一段正在落字，可按 Esc 取消」。
- 每次会话有单调递增 `sessionId` 和取消令牌。HTTP abort、本地推理 cancel 都是尽力而为；真正的安全线是晚到结果必须因 `sessionId` 过期而被丢弃。
- 所有成功、失败、取消和应用异常退出路径都进入同一清理逻辑；临时音频不因请求失败而残留。
- 应用启动时清理上次异常退出遗留且超过 24 小时的临时音频。

工作台修改另有一条轻量状态线，不与 ASR 交付状态混成一团：

```text
EditIdle
  └─ start instruction ─► CapturingInstruction
                            └─ stop ─► TranscribingInstruction
                                         └─ success ─► Planning
                                                         ├─ low / medium risk ─► Applying ─► EditIdle
                                                         ├─ high risk ─► Previewing
                                                         │                  ├─ apply ─► Applying ─► EditIdle
                                                         │                  └─ cancel ─► EditIdle
                                                         └─ fail / stale / cancel ─► EditIdle
```

- 全 App 同时只占用一个麦克风会话；转写正文和转写修改指令不能并行录音。
- AI 正在规划修改时，用户仍可手动编辑；每次请求携带正文版本，版本不符就丢弃结果。用户又发起新的语音动作时，取消旧修改任务，以最新意图为准；已发出的远程请求可能仍产生处理或费用。
- 高风险预览出现后**不持续监听麦克风**。用户可按回车 / `Esc`，也可再次按住「语音修改」说「应用」或「取消」；主快捷键会先放弃预览，再开始正常续写。

## 6. 托盘 / 菜单栏

双端都有「状态图标 + 左键面板 + 右键菜单」。Windows 用语为系统托盘；macOS 为菜单栏。产品文案统一称「落字图标」。

### 6.1 图标状态

- 常态：单色「落光标」线稿，完全静止
- 录音中：极光青字点与两侧回声弧做低频呼吸，不让整个图标闪烁
- 转写中：字点沿输入基线完成一次短移动，之后保持静态处理态
- 完成：冰白 / 极光青亮一次，约 1.5s 恢复常态
- 待确认：琥珀小点；错误：风险红小点，约 3s 后回到常态并保留可查看状态
- 菜单栏 / 托盘无法可靠显示彩色时，改用线型和小徽标变化，不以颜色作为唯一信息

### 6.2 左键：迷你面板

迷你面板不是仪表盘，也不堆配置卡片。默认结构：

```text
┌──────────────────────────────┐
│ 落字                  本地就绪 │
│                              │
│       [  继续说  ]            │
│                              │
│ 最近：今天下午三点开会…   复制 │
│ 打开语音草稿              ··· │
└──────────────────────────────┘
```

- 只保留一个极光青主动作「继续说」；开关录音模式时文案变为「开始说 / 停止」。
- 最近一次结果只显示一行，并遵守安全输入和 10 分钟内存有效期；没有结果时整行隐藏。
- 「打开语音草稿」是明确的次级入口；试录、设置、权限和引擎切换进入 `···` 或右键菜单。
- 面板关闭后停止内部动画和文本测量，不保持高频 WebView 活动。

## 7. 悬浮录音条

```
待机              录音中                         转写中
  │·      →       │·  ▁▃▆▃▂  正在听 · Esc   →    │●  落字中
```

- 不抢键盘焦点（Mac：`nonactivating`；Win：工具窗 / 不激活样式）
- 默认靠近主屏底部居中，避开任务栏 / Dock
- 状态文案：`听写中` / `落字中` / `已落字` / `未找到输入框` / `引擎未就绪`
- 左侧始终使用「落光标」状态图形，不再显示通用麦克风图标或多柱均衡器 Logo。
- 玻璃胶囊按状态原位伸缩；只在录音时展示低采样率的简化波形和 `Esc` 取消提示，完成后收回，不留下常驻工具条。
- 正常录音使用极光青；修改指令使用电光蓝；需要确认使用琥珀；失败才使用风险红。
- 松手后字点向输入基线移动约 4 px，再进入「落字中」；完成只亮一次，不播放循环成功动画。
- 降低透明度时使用高对比实体胶囊；减少动态效果时不位移，只切换图形、文案和颜色。

### 7.1 统一界面结构：一个文稿，一个语音控件

落字只有一个完整编辑界面「语音草稿工作台」，不再创建“转写、纠错、润色、粘贴美化”四个页面或四种模式。

```text
┌──────────────────────────────────────────────────┐
│  落字 · 语音草稿               复制  ···         │  ← 轻薄系统玻璃工具栏
├──────────────────────────────────────────────────┤
│                                                  │
│  正文内容；正常选择、输入、粘贴和换行              │  ← 稳定高可读内容层
│  疑似词用线型标记，AI 改动只短暂显示               │
│                                                  │
│             [ 继续说 ]   说修改                   │  ← 底部落光语音控件
└──────────────────────────────────────────────────┘
```

- 窗口采用单栏正文结构，无侧边栏、无文档列表、无模式导航；默认建议尺寸约 `760 × 600`，允许正常缩放。
- 默认直接显示正文，不先显示欢迎页、模板选择或功能卡片。空草稿只显示：`说点什么，或直接粘贴`。
- 顶部只保留窗口级动作：复制、更多；导出与设置进入 `···`。自动保存状态只在保存中、失败或刚恢复草稿时短暂出现。
- 底部「继续说」是唯一视觉主按钮；「说修改」作为较弱的次级文字入口，只在草稿非空时出现，第二快捷键始终可直接触发。
- 底部语音控件根据状态在「继续说、正在听、正在转写、说出修改要求、等待确认」之间原位形变。
- 所有语音能力都围绕当前草稿生效，不出现聊天消息流、机器人头像或左右对话气泡。
- 工具栏、语音控件和短提示可以使用系统玻璃；正文背景、长内容和设置列表禁止铺满玻璃或常驻渐变。
- macOS 使用原生工具栏与系统材质；Windows 保留系统窗口习惯和 Mica / Acrylic 层级，不复制 macOS 窗口按钮与触控尺寸。

底部语音控件的视觉状态固定为：

```text
继续说 → 正在听 → 落字中 → 已写入
       ↘ 说出修改要求 → 正在修改 → 已修改 · 撤销
```

- 录音态显示简化呼吸声纹；转写态只让字点完成一次基线移动，不使用占据正文的大型 Loading。
- 正文续写使用极光青，修改指令使用电光蓝；高风险预览不持续监听麦克风。
- `已写入`、`已修改 · 撤销` 等反馈约 1.5s 后自行收起，不要求用户点确认。

### 7.2 语音草稿工作台

#### 7.2.1 草稿生命周期

- 同时只有一份活动草稿；关闭工作台不会退出托盘常驻能力。
- 草稿每次编辑后延迟约 1 秒自动保存到本机应用目录；关闭窗口或退出 App 前必须把待保存内容原子落盘。保存失败时保留窗口与内存恢复副本并明确提示，不能假装关闭后静默丢稿。
- 只持久化当前正文、必要标注和最多 20 步差异修订，用于恢复与撤销；它仍是一份当前草稿，不等于多文档历史库。
- 异常退出后首次重开恢复当前草稿；用户主动「清空草稿」时二次确认，并清除恢复文件。
- 默认上限 30,000 个字符；超过上限仍可基础编辑和复制，但全文 AI 操作必须先选择范围，避免一次请求过大。
- 工作台关闭后立即停止光标动画、文本测量和拼写分析；无待处理保存时不保留后台 WebView 活跃任务。

#### 7.2.2 三种输入来源，共用同一正文

| 来源 | 行为 |
|---|---|
| 语音续写 | 主快捷键录音，结果替换当前选区或插入当前光标；没有光标时追加到文末 |
| 快捷落字转入 | 从成功反馈或托盘执行「在语音草稿中继续」，把本次结果放入当前草稿 |
| 最近一次落字 | 草稿为空且触发「语音修改」时，可载入落字自己的最近一次转写；不读取外部 App 当前正文 |
| 粘贴文字 | 使用系统粘贴；只写入正文，不自动上传、不自动润色 |

最近一次落字只在内存保存 10 分钟，并在载入、下一次成功落字或退出 App 后失效；它不是历史记录，也不在托盘长期展示全文。

语音转写的段落规则：

1. 用户明确说「换行」「另起一段」「第一点」时优先按指令排版，并从最终正文中移除控制词。
2. 没有明确控制词时，使用停顿、句意和列表语义共同分段，不仅按固定秒数机械断行。
3. 短句默认连续成段；明显话题切换、列举或较长停顿才新起一段，避免一句一行。
4. 工作台内的原有换行默认锁定；AI 修改局部文本时不得顺便重排无关段落。

### 7.3 两种语音动作

#### 7.3.1 继续说

- 作用是增加正文，不解释为命令。
- 用户说「换行」等少量排版控制词时只影响本次新增内容。
- 转写结束先插入可读结果；深度 AI 不可用时仍能得到文本。

#### 7.3.2 说出修改要求

第二快捷键或语音控件的次级入口进入修改指令录音。用户只需要自然表达，例如：

- 「把这一段改得更简洁」
- 「修一下错别字，名字和数字不要动」
- 「整理成三点」
- 「把语气改得正式一点」
- 「第二段删掉重复的话」
- 「撤销刚才的修改」

作用范围按以下顺序确定：

1. 有文字选区 → 只修改选区。
2. 无选区但有光标 → 默认修改当前自然段。
3. 指令明确说「第二段」「标题」「全文」 → 使用明确对象。
4. 指令没有范围且当前段无法确定 → 先用语音 / 短提示追问范围，不擅自改全文。

MVP 不要求用户先选择「纠错 / 润色 / 改写」模式；内部根据指令路由到对应文本操作。三个能力的产品语义是：

| 能力 | 默认边界 |
|---|---|
| 纠错 | 修正错字、标点、明显口头重复和病句；不得主动改观点 |
| 润色 | 保持事实与结构，提升通顺度和表达完整性 |
| 按指令修改 | 允许改长度、语气、结构或指定内容，但严格受作用范围与风险确认约束 |

「撤销」「重做」「应用」「取消」「下一个疑似词」「这个词没错」属于本机命令，不需要文本 AI。自然语言纠错、润色、改写和结构调整才需要已配置的文本 AI。

### 7.4 修改应用、风险确认与撤销

为减少“点点点”，低风险修改直接应用并给出短暂撤销入口；高风险修改不静默覆盖。

| 风险 | 例子 | 行为 |
|---|---|---|
| 低 | 标点、错字、去口头重复、调整一句话 | 自动应用；玻璃提示显示「已修改 · 撤销」 |
| 中 | 改写当前段、调整语气、重组列表 | 自动应用并保留改前快照；AI 改动短暂标蓝 |
| 高 | 改全文、删除超过作用范围 30%、改变数字 / 日期 / 人名 / 专有名词 | 展示前后预览；用户说「应用」或按回车确认，说「取消」或按 Esc 放弃 |

- 高风险预览使用窗口中央的系统 sheet，不打开永久右侧栏；只显示受影响范围、关键差异和风险原因。
- 预览只有两个主决策：`应用`、`取消`；键盘回车 / `Esc` 和再次按住语音修改说「应用 / 取消」与按钮语义一致。
- 受保护的数字、日期、人名和项目名使用风险红双点下划线突出；其余增删保持系统差异样式，避免整页红蓝底色。

- 每次 AI 修改形成一个可逆修订，最多保留 20 步；正文使用差异补丁保存，不复制 20 份完整长文。
- `⌘Z / Ctrl+Z` 与语音「撤销」走同一修订栈；`⌘⇧Z`、`Ctrl+Y / Ctrl+Shift+Z` 与语音「重做」走同一重做栈；「恢复刚才的版本」等价于撤销最近一次 AI 修改。
- AI 返回失败、超时、格式不合法或越过作用范围时，正文保持不变；不得先清空再等待结果。
- 正文中的数字、日期、人名、项目名和英文缩写默认作为保护片段；指令未明确要求改变时，AI 输出若改动这些片段则升级为高风险。

### 7.5 疑似错字与 AI 改动标记

标记只帮助确认，不把文稿变成满屏批注：

| 样式 | 含义 | 处理 |
|---|---|---|
| 琥珀细波浪线 | ASR 置信较低、同音词或生僻词，建议确认 | 点击、键盘跳转，或说「下一个疑似词」 |
| 红色双点下划线 | 数字、日期、姓名、项目名冲突等高风险项 | 复制前不阻断，但工作台显示一条简短提醒 |
| 电光蓝浅底 / 实线下划线 | 本次 AI 新改内容 | 约 10 秒后淡出；修订记录仍可撤销 |

- 明确修正后的标记立即消失；同一个词被用户确认后，本次草稿内不重复提示。
- 用户可说「把第一个改成胜算 BI」「这个词没错」「读出有问题的地方」完成处理。
- 复制、导出和快捷插入只输出纯文本与正常换行，不携带颜色、下划线或内部置信数据；未确认标记不阻止复制，只用非模态短提示说明「仍有 2 处待确认，已复制」。

### 7.6 市面能力参考与原创边界

成熟产品已经验证了三种低摩擦模式：全局快捷键直接落字、转写后自动清理成文、选择文字后用语音下修改指令。落字吸收这些**能力规律**，但不复制它们的品牌、界面、文案、订阅逻辑或专有交互。

- Typeless：口头重复 / 填充词清理、自动排版、选中文字后语音修改。
- Superwhisper：语音识别与可选语言模型分成前后两层，允许纯转写或智能处理。
- Wispr Flow Command Mode：用独立快捷键录制修改命令，并对选中文字执行改写。

落字的差异化取舍是：保留全局快捷输入，同时把复杂修改收进一个本地、单草稿、无聊天记录的工作台；首版不在后台读取任意 App 的正文。

## 8. 转写体系（重点）

```text
录音结束
   │
   ├─ 仅本地 ──► LocalEngine
   ├─ 仅云端 ──► CloudEngine
   └─ 自动   ──► EngineRouter
                    ├─ 本地已就绪：只走 LocalEngine
                    ├─ 本地不可用 / 失败，且云端已配置并授权：走 CloudEngine
                    └─ 两侧都不可用：进入配置引导
                            │
                            ▼
                    ConservativeCleanup
                    ├─ 本地标点 / 分段 / 明显重复
                    ├─ 已授权文本 AI：限时保守成文
                    └─ 不可用 / 超时：直接交付原始转写

二期高级「竞速」开启后才会并发 LocalEngine + CloudEngine；先完成者胜出，
另一路尽力取消，但可能已经产生云端处理、计费或数据留存。
```

### 8.1 本地转写

#### 8.1.0 MVP 运行时基线

- 唯一必达本地主路径：随应用集成 `whisper.cpp` 兼容运行时；Mac 走 Metal，Windows 优先探测可用加速，失败必须回退 CPU。
- 模型格式只承诺经过应用验证的 GGML 文件；首装根据硬件选择轻量档，不把 `small` 硬塞给所有机器：内存 ≤8 GiB、仅 CPU 或内存压力较高时推荐多语言 `base` 量化模型；内存 ≥16 GiB 且加速后端可用时推荐多语言 `small` 量化模型；中间档以实测速度和可用内存决定。检测结果与预计占用必须展示，用户可以手动改选。
- 模型清单字段至少包含：`id`、展示名、语言、量化、字节数、SHA256、下载源、许可证、最低运行时版本。
- 自选模型先校验文件存在、大小、格式头和运行时可加载性；校验失败不得设为当前模型或进入按需加载。
- Apple Speech / Windows Speech 仅作为后续实验适配器：Apple 是否真正离线取决于 `supportsOnDeviceRecognition`；Windows 不同 API 还受联网、语言包和应用包身份限制，不能作为双端一致性承诺。
- Ollama 不进 MVP：其音频模型与调用方式需要模型级适配，不能仅凭“发现了模型名”就视为可用 ASR 后端。

#### 8.1.1 自带检测（启动后与进入设置时刷新）

| 检测项 | macOS | Windows | 用户看到 |
|---|---|---|---|
| 落字运行时 | `whisper.cpp` + Metal / CPU 能否初始化 | `whisper.cpp` + 可用加速 / CPU 能否初始化 | 就绪 / 仅 CPU / 初始化失败 |
| 落字推荐模型 | `~/Library/Application Support/Luozi/models/` | `%APPDATA%\Luozi\models\` | 已安装 / 未安装 / 校验失败 |
| 用户自选模型文件 | 路径仍存在 | 同 | 有效 / 失效 |
| 磁盘与内存 | 下载前空间、首次加载时内存是否足够 | 同 | 可用 / 空间不足 / 建议轻量档 |

「本机能力」卡片 +「重新检测」。某平台没有的后端（如 Apple Speech）在该平台隐藏，不显示灰掉半残入口。

#### 8.1.2 无模型时：下载与教程（必做，分平台）

1. **一键下载本机推荐模型**（按硬件选 `base` / `small` 量化档；显示选择原因、体积、路径、哈希；可暂停/重试；完成后设为当前，用户试录时首次加载）
2. **备用下载链接**（可复制；浏览器下完再「选择模型文件」）
3. **小白教程**（应用内 + 仓库 `docs/tutorials/`）

| 教程章节 | 内容 |
|---|---|
| A. 最省事 | 一键下载 → 自动/仅本地 → 试录 |
| B. 手动文件 | 链接下载 → 选择文件 → 校验 → 测试本地 |
| C. 常见失败 | 磁盘、内存、权限、架构（arm64/x64）、代理、文件不完整、杀毒拦截（Win） |
| D. 实验后端 | 二期再提供系统语音 / Ollama 的独立说明，不混入 MVP 主教程 |

#### 8.1.3 本地配置项

| 项 | 说明 | 默认 |
|---|---|---|
| 启用本地 | 总开关 | 开 |
| 后端 | 落字 Whisper；实验适配器二期单独出现 | 落字 Whisper |
| 当前模型 | 检测结果 + 已下载 + 自选 | 本机推荐档 |
| 选择模型文件… | 系统文件框 | — |
| 模型目录 | 可「在资源管理器/Finder 中显示」 | 见上表平台路径 |
| 设备 | Auto / CPU / 可用加速后端（只有检测成功才显示） | Auto |
| 模型保温 | 首次转写后保留一段时间；不在登录启动时加载 | 5 分钟 |
| 测试本地 | 约 2 秒测延迟 | — |

本地不需要 API Key。本机 OpenAI 兼容网关归云端节，Base URL 填 `http://127.0.0.1:...`。

#### 8.1.4 音频管线

1. 使用系统默认麦克风；录制为单声道 PCM，统一重采样为 16 kHz、16-bit WAV 后交给本地或云端。
2. MVP 单次录音范围为 0.3–30 秒；30 秒足以覆盖快捷输入，也与限制最严的默认云端预设对齐。更长录音与分片合并放二期。
3. 结束录音后做轻量静音裁剪；裁剪后无有效人声则按误触处理，不调用引擎。
4. 临时文件使用随机名和当前用户私有权限；交付或失败后立即删除，异常退出遗留由启动清理兜底。
5. 麦克风切换、采样率不支持、设备被占用、录音中拔出设备都必须返回可区分错误，不统一显示“转写失败”。

### 8.2 云端 / API

#### 8.2.1 协议基线

共享 `CloudEngine` 只负责超时、取消、错误归一化和安全策略；具体请求与响应由 `ProviderAdapter` 处理，不能假设所有厂商都完全兼容：

```text
CloudEngine
  ├─ OpenAICompatibleAdapter
  ├─ GroqAdapter
  ├─ SiliconFlowAdapter
  ├─ ZhipuAdapter
  └─ CustomAdapter（用户显式填写）
```

通用基线：

- `POST {baseURL}/audio/transcriptions`（路径可改）
- `multipart`：`file` + `model` + 可选 `language`、`prompt`、厂商字段
- `Authorization: Bearer {API Key}`
- 响应适配为统一 `Transcript{text, language?, durationMs, engineId}`
- 超时默认 15 秒；不自动重试会产生计费的 POST。用户点「重试」才重新发送。

| 项 | 说明 |
|---|---|
| API Base URL | 例 `https://api.groq.com/openai/v1` |
| API Key | 系统凭据库（Mac Keychain / Windows Credential Manager 或 DPAPI） |
| 模型名 | 可空 |
| 请求路径 | 默认 `/audio/transcriptions` |
| 额外 Header / 表单 | 高级折叠 |

安全约束：

- 远程地址默认只允许 HTTPS；HTTP 仅允许 `localhost` / `127.0.0.1` / `::1`。
- 禁止把 `Authorization` 头跨域转发；厂商请求默认不跟随跨主机重定向。
- 自定义 Header 禁止覆盖 `Host`、`Content-Length` 和应用生成的凭据头。
- 日志只记录适配器、状态码、耗时和匿名错误码，不记录 Key、音频、转写正文及含查询参数的完整 URL。

#### 8.2.2 提供方预设

> 价格、免费额度、模型和数据政策都会变化；预设只提供经过当前版本验证的配置，不承诺永久免费，也不内置 Key。

| 预设 | Base URL | 推荐模型 | 备注 |
|---|---|---|---|
| Groq | `https://api.groq.com/openai/v1` | `whisper-large-v3-turbo` | 低延迟；短音频也可能按最低时长计费；数据政策由用户查看并同意 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall` | 当前接口为 `/audio/transcriptions`；模型下线或变更时由预设版本更新 |
| 智谱 GLM-ASR | `https://open.bigmodel.cn/api/paas/v4` | `glm-asr-2512` | `stream=false`；当前文件限制 25 MB / 30 秒 |
| 自定义 OpenAI 兼容 | 自填 | 自填 | 内网/学校/其它免费网关 |
| 本机兼容网关 | `http://127.0.0.1:端口/v1` | 自填 | 流量不出机 |

**兼容原则**：协议优先、厂商差异显式适配；Key 分预设隔离；预设配置带版本号；永不把 Key 写进仓库或日志。

#### 8.2.3 配置范围

MVP 同时启用一套云端配置；切换预设不串 Key。多配置档二期。

首次启用某一提供方时必须显示并记录本机同意状态：

- 将上传：本次录音文件及用户填写的语言 / 提示词。
- 上传到：实际请求主机名。
- 用途与留存：链接到该提供方当前数据政策，不由落字代替承诺。
- 同意按 `providerId + baseURL 主机` 隔离；主机改变后必须重新确认。
- 关闭该提供方或清除 Key 时，同时清除同意状态。

### 8.3 「自动」与「快」

| 规则 | 行为 |
|---|---|
| 模型加载 | 首次本地转写时按需加载；完成后默认保温 5 分钟，空闲再释放 |
| 自动 | 本地已就绪时只走本地；本地不可用或失败时，只有已授权云端才可接管 |
| 竞速 | 二期高级选项，默认关；开启前再次提示同段音频会上传，且取消不保证免计费/免处理 |
| 最短/最长录音 | 0.3s / 30s |
| 前处理 | 轻量静音裁剪；重降噪默认关 |
| 快捷主路径 | 本地规则先做标点、分段和明显重复；用户已单独开启「快捷落字使用 AI」时，再按内容复杂度判断是否需要模型，不让用户每次选模式 |
| 快捷文本 AI 时限 | 额外等待最多 1.2 秒；超时、取消或校验失败立即回退本地整理结果 |
| 深度处理 | 只在工作台内由用户明确发起；翻译不进 MVP |

速度页分别展示 ASR、本地整理和文本 AI 最近 20 次成功请求的 P50 / P95，不用单次绿色数字制造稳定性错觉；发布记录同时给出“快速落字”和“AI 成文”两条延迟口径。

### 8.4 失败与降级

| 情况 | 行为 |
|---|---|
| 仅本地但未就绪 | 引导下载 / 教程 / 改自动或云端 |
| 云端 401/403 | Key 或额度问题 + 外开申请页 |
| 云端 429 | 显示限流，不自动重试；允许切回本地 |
| 云端超时 | 不自动重发；自动模式只有尚未尝试过且已就绪的本地引擎可接管 |
| 快捷落字的文本 AI 不可用 / 超时 | 直接交付保守规则整理或原始转写，不显示成主要失败 |
| 工作台文本 AI 未配置 / 未授权 | 第一次触发时打开最小配置；取消则正文保持不变，继续基础编辑 |
| AI 结果返回时正文已变化 | 标记结果已过期并丢弃，不覆盖用户的新内容 |
| AI 改动保护片段或越过范围 | 不自动应用；进入高风险预览或直接拒绝无效补丁 |
| 插入失败 | 降级剪贴板路径：自动写入 + 「已落到剪贴板（插入未成功）」 |
| 无焦点成功 | 自动剪贴板 + 反馈条（非「请点击复制」） |
| 目标在转写时变化 | 不向新焦点插入，自动剪贴板 + 「目标已变化，结果已复制」 |
| 安全输入目标 | 开始前识别到则拒绝录音；交付时才识别到则丢弃结果，不写剪贴板 |
| 双败 | 独立 `retryBuffer` 在内存中保留音频最多 60 秒供用户主动重试；落盘临时文件仍按清理规则处理 |

### 8.5 统一错误契约

底层错误归一化为稳定 `errorCode`，UI 文案按平台本地化；实现计划和测试不能依赖厂商原始字符串：

| 类别 | 稳定错误码 |
|---|---|
| 权限 / 热键 | `microphone_denied`、`accessibility_denied`、`hotkey_conflict` |
| 录音 | `audio_device_missing`、`audio_device_lost`、`audio_format_unsupported`、`no_speech` |
| 本地模型 | `model_missing`、`model_checksum_failed`、`model_load_failed`、`local_inference_failed` |
| 云端 | `cloud_not_consented`、`cloud_unauthorized`、`cloud_rate_limited`、`cloud_timeout`、`cloud_protocol_error` |
| 交付 | `target_changed`、`target_unsupported`、`safety_blocked`、`insert_failed`、`clipboard_failed` |
| 会话 | `session_busy`、`session_canceled`、`stale_result_discarded` |
| 文本 AI | `text_ai_not_configured`、`text_ai_not_consented`、`text_ai_timeout`、`text_ai_invalid_patch`、`protected_token_changed`、`edit_scope_invalid` |

原始错误只作为脱敏后的调试附加信息；用户可见层必须说明下一步，例如重新授权、换快捷键、下载模型、检查 Key 或改走剪贴板。

### 8.6 文本 AI 与成文管线

ASR 与文本 AI 是两个独立能力，不能因为某家服务同时支持两者就耦合成一个不可替换模块：

```text
语音 / 粘贴文字
      │
      ├─ 快捷落字 ─► 保守整理 ─► 直接交付
      │
      └─ 工作台指令 ─► EditPlanner ─► TextAIProvider
                                      │
                                      ├─ 作用范围补丁
                                      ├─ 疑似错误标注
                                      └─ 风险信息
```

#### 8.6.1 提供方式

- MVP 支持用户配置的 OpenAI 兼容文本接口，以及本机 loopback 兼容服务。
- 落字不提供账号、官方中转服务、共享 Key 或默认免费额度；远程费用、限额与数据政策归用户选择的提供方，本机服务由用户自行运行。
- 文本 AI 的 Base URL、模型、Key、授权状态与 ASR 云端配置分开保存；两者可以使用同一厂商，但不能默认复用授权。
- 不在安装包中捆绑本地大语言模型；后续若增加本地模型，也必须独立下载、按需加载，并保持工作台无模型时仍可基础编辑。
- 粘贴文字不会因进入工作台而自动发送；只有用户触发纠错、润色或修改时，才发送本次所需的最小范围和必要上下文。
- 第一次真正触发深度 AI 时，原位打开一次性最小配置：`Base URL`、Key、模型、连接测试与上传内容说明；本机 loopback 可不填 Key。连接和授权成功后自动继续刚才那条语音指令，不要求用户重新说一遍；取消、测试失败或关闭窗口都不改变正文。
- 工作台按需修改与「快捷落字使用 AI」是两个上传范围。首次配置只授权当前工作台操作，不静默开启每次落字上传；用户在设置中单独开启快捷成文后，才允许把后续转写文本发送给文本 AI。

#### 8.6.2 输出约束

- 文本 AI 返回的是「指定范围的替换结果 + 标注 + 风险」，不是默认返回整篇文稿。
- 应用先校验作用范围、正文版本和保护片段，再决定自动应用或进入预览。
- 请求发出后正文仍可编辑；返回时若相关范围已变化，则结果标记过期，不覆盖用户的新编辑。
- 草稿正文、粘贴内容和引用文字一律作为**待处理数据**，其中出现的“忽略要求”“发送全文”等文字不得成为模型指令；只有用户本次语音 / 键盘发出的修改要求能定义动作。
- 默认只发送目标范围以及前后各最多一个自然段作为上下文；只有用户明确要求全文处理时才发送全文。AI 结果只能替换已授权范围，不能借内容中的指令扩大读取或改写边界。
- AI 不得生成隐藏格式、远程资源或可执行内容；工作台只接受纯文本、正常换行和有限列表结构。
- 快捷落字的保守成文设置短超时预算；超时立即回退原始转写。工作台深度处理可等待更久，但始终允许 Esc 取消。

## 11. 技术架构（跨平台）

### 11.1 选型结论

| 路线 | 结论 |
|---|---|
| 双端各写一套原生（Swift + C#） | 交互最贴，成本高、行为易分叉 → **不采用为唯一方案** |
| Electron | 双端快，但包体/内存差，与「快+轻」略冲 → 备选 |
| **Tauri 2 + Rust 核心** | 包体较轻、双端一条流水线、系统托盘/全局快捷键生态成熟 → **推荐采用** |

Tauri 只负责共享壳和业务 UI，不代表用网页效果伪造所有系统材质：

- macOS 新系统通过窄平台桥接使用系统 Liquid Glass / AppKit 材质；旧系统降级为标准 vibrancy，不追求像素级仿制。
- Windows 使用 DWM Mica / Acrylic 或系统等价材质；不把 macOS 圆点窗口、菜单和触控尺寸硬搬过去。
- 正文编辑区使用普通高对比内容面；只有工具栏、录音胶囊、确认浮层采用系统材质。

### 11.2 模块划分

```text
apps/luozi/   （或公开仓根目录）
  crates/
    luozi-core/          # 状态机、引擎路由、转写协议、交付规则、配置 schema（纯逻辑可单测）
  src-tauri/
    src/
      audio/             # 录音、重采样、静音裁剪、临时文件
      engines/
        asr/             # whisper.cpp、本地模型、CloudEngine、ProviderAdapter
        text_ai/         # TextAIProvider、保守成文、修改补丁与风险校验
      draft/             # 单草稿、光标/选区范围、修订栈、标注、崩溃恢复
      platform/          # cfg 分平台：热键、目标捕获/插入、凭据、路径、开机启动
      app/               # Tauri 命令、托盘、窗口、生命周期
    capabilities/        # Tauri 权限声明
  ui/                    # 工作台 / 设置 / 迷你面板 / 录音条 / 教程
  model-manifest/        # 版本化模型清单与哈希；不存模型大文件
  tests/
    fixtures/            # 脱敏响应样例、音频基线说明（大音频不进 Git）
    manual/              # Mac / Windows 兼容性测试表
  docs/
    tutorials/           # 分平台教程
  scripts/
    package-macos.sh
    package-windows.*
    checksums.sh
  .github/workflows/
    release.yml          # tag 触发双端构建并挂 Release
  CHANGELOG.md
  LICENSE
  README.md
  README.zh-CN.md
```

#### 草稿正文的单一真相源

- 前端编辑器负责渲染、选区、光标和 IME 组合态；Rust 核心负责规范正文、单调递增 `revision`、差异修订、标注锚点和原子自动保存，避免 WebView 与后台各存一份互相覆盖。
- 手动编辑、语音续写和 AI 补丁都携带 `baseRevision`；核心只接受基于当前版本的变更，过期补丁返回 `stale_result_discarded`。
- 中文输入法仍在组合中的文字只留在前端，提交组合后才形成正文变更；录音结果不得打断或覆盖未提交候选。
- MVP 是支持装饰标记的**纯文本编辑器**，只保留正常换行与有限列表语义，不引入富文本 DOM、HTML 粘贴或协同编辑框架。

平台适配实现：

- `platform-macos`：Accessibility 插入、Keychain、菜单栏、Login Item
- `platform-windows`：UI Automation / 剪贴板回退、Credential Manager、托盘、开机启动

先保留一个 `luozi-core` 纯逻辑 crate，平台实现放 `src-tauri` 的条件编译模块；只有当平台层出现独立复用需求时才拆第二个 crate，避免仓库骨架先于真实边界过度分层。

共享：会话状态机、`EngineRouter`、`EditPlanner`、保护片段校验、OpenAI 兼容客户端、厂商适配器、`ModelDetector/Downloader`、设置 schema。`RaceEngine` 二期实现，但接口预留不影响 MVP。

### 11.3 核心接口契约

```rust
trait TranscriptionEngine {
    fn id(&self) -> EngineId;
    async fn readiness(&self) -> Readiness;
    async fn transcribe(
        &self,
        audio: AudioInput,
        options: TranscribeOptions,
        cancel: CancellationToken,
    ) -> Result<Transcript, TranscribeError>;
}

trait DeliveryPlatform {
    async fn capture_target(&self) -> Option<TargetToken>;
    async fn validate_target(&self, target: &TargetToken) -> TargetState;
    async fn insert_text(&self, target: &TargetToken, text: &str) -> Result<(), DeliveryError>;
    async fn write_clipboard(&self, text: &str) -> Result<ClipboardReceipt, DeliveryError>;
}
```

统一数据对象：

| 对象 | 必需字段 |
|---|---|
| `AudioInput` | `sessionId`、本地临时句柄、时长、采样率、声道、字节数 |
| `TranscribeOptions` | 语言、可选提示词、30 秒超时上限、引擎配置引用 |
| `Transcript` | `text`、`engineId`、`elapsedMs`、可选语言 / 置信信息 |
| `TargetToken` | 平台、进程、窗口、元素身份、捕获时间；不含输入内容 |
| `ClipboardReceipt` | 写入后的序列号 / change count、结果摘要、可选上一份普通文本快照 |
| `AppConfig` | `schemaVersion`、通用设置、引擎设置、凭据引用；不含 Key 明文 |

配置 JSON 采用 `schemaVersion` 迁移；先写临时文件、校验成功后原子替换。迁移失败保留旧配置并进入可恢复提示，不能静默重置用户设置。

### 11.4 插入策略

1. 捕获并复核原输入目标，再走平台原生「写入焦点」。
2. 目标变化、不可确认或写入失败 → 剪贴板 + Toast「已复制，请粘贴」。
3. 模拟粘贴快捷键仅作二期高级项；它会临时改剪贴板并可能被安全软件拦截，不进入 MVP。

### 11.5 必须先做的跨平台风险 Spike

在大规模搭 UI 和模型下载器前，先用最小壳验证五件事：

1. Tauri 全局快捷键能在 Mac / Windows 稳定收到 `Pressed` / `Released`，支持按住说话；注册冲突能被检测。
2. 悬浮条出现和更新不抢目标输入焦点。
3. 捕获目标、延时 2 秒、复核并写入；中途切窗口时必须降级剪贴板。
4. 麦克风权限、Accessibility / UIA、未签名安装包在目标系统上的真实提示和失败路径。
5. Tauri 窗口能否在 macOS / Windows 接入系统材质、降低透明度设置和不激活悬浮窗；新 Liquid Glass API 不可用时能自动降级。

若官方全局快捷键插件在某平台无法稳定提供释放事件，再只对该平台落低级键盘监听适配器，并把新增权限 / 杀毒风险写入权限页；不预先两端都上低级钩子。

若新 Liquid Glass API 只支持较新系统，旧系统必须自动降级，不能为了效果抬高整个产品最低系统版本。

### 11.6 轻量化生命周期与性能预算

#### 11.6.1 进程与模块生命周期

| 状态 | 保留 | 必须释放 / 停止 |
|---|---|---|
| 后台待机 | 托盘、全局热键、极小状态机 | 工作台窗口、ASR 模型、文本 AI 请求、波形、计时动画 |
| 录音中 | 音频采集、目标令牌、悬浮条 | 文本 AI、全文分析 |
| 转写 / 修改中 | 当前任务需要的引擎、取消令牌 | 其它模型和无关提供方 |
| 工作台打开空闲 | 编辑器、当前草稿、最多 20 步差异修订 | 音频缓冲、后台全文扫描、持续语法模型 |
| 工作台关闭 | 草稿恢复文件、托盘 | WebView 活跃计时器、光标测量、标注计算、编辑器缓存 |

- 默认不在开机启动时加载 ASR 模型；第一次本地转写承担冷启动，之后保温 5 分钟。
- 用户连续使用时只复用同一份模型实例；不得每句话重复加载。
- 电池供电、系统低电量或内存压力出现时立即取消保温；用户可在高级设置改为 0 / 5 / 15 分钟。
- 文本 AI 仅通过网络请求或用户自备本机服务运行，App 内不常驻推理进程。
- 不轮询剪贴板、不监听全部键盘内容、不后台索引草稿；全局热键使用系统事件驱动。

#### 11.6.2 发布性能指标

以下指标在一台基线 Mac 和一台基线 Windows 机器上记录冷 / 热两组数据：

| 指标 | `v0.1.0` 目标 |
|---|---|
| 托盘空闲 CPU | 连续 5 分钟 P95 ≤0.5% |
| 托盘空闲私有内存 | 不含已卸载 ASR 模型，目标 ≤120 MiB |
| 工作台打开但无任务 | 目标 ≤200 MiB，静止 30 秒后无持续增长 |
| 模型释放 | 到达空闲时限后 60 秒内释放主要模型内存；回落值写进测试记录 |
| 隐藏窗口 GPU | 无持续渲染；减少动态效果时录音条不做连续折射动画 |
| 长时间稳定性 | 连续 100 次短句和 30 次 AI 修改后，无句柄 / 临时文件泄漏，空闲内存回落到稳定区间 |

WebView 与系统共享进程在不同平台统计方式不同，测试记录必须同时给出「应用私有工作集」和「相关进程合计」，不能只挑较小数字。

## 13. 数据与安全

| 项 | macOS | Windows |
|---|---|---|
| 偏好 | 应用支持目录 JSON / 系统偏好封装 | `%APPDATA%\Luozi\` |
| API Key | Keychain | Credential Manager / DPAPI |
| 音频 | 用户私有临时文件，成功 / 失败 / 取消后删；启动清理异常残留 | 同 |
| 草稿 | 只保存当前活动草稿与崩溃恢复信息；无文档历史库 | 同 |
| 修订 | 最多 20 步文本差异；清空草稿时同步清除 | 同 |
| 最近一次落字 | 仅内存、最多 10 分钟；载入、被新结果替换或退出 App 后清除 | 同 |
| 剪贴板快照 | 只在内存保存 ≤1 MiB 普通文本，≤60 秒 | 同 |
| 崩溃 / 诊断 | 无 Key、无音频、无转写正文、无目标输入内容 | 同 |

补充安全规则：

1. 模型下载先检查空间，写 `.partial`，完成后校验 SHA256，再原子改名；校验失败不得加载。
2. 云端 Key 的配置文件里只保存凭据库条目 ID；删除配置时同步删除凭据与同意状态。
3. 自定义远程 Base URL 默认必须 HTTPS；本机 HTTP 仅允许 loopback。
4. 诊断导出前再做一次脱敏扫描，并让用户预览文件列表；默认不包含音频和转写内容。
5. 反馈条在锁屏、安全输入和密码框场景不展示全文；托盘“最近一次结果”同样受此限制。
6. 文本 AI 只发送当前操作范围和必要上下文；日志不记录粘贴正文、语音修改指令和 AI 输出全文。
7. 草稿恢复文件使用当前用户私有权限；设置提供「立即清空草稿与修订」，退出 App 不默认删除，以免意外丢稿。
8. 系统锁屏、切到安全桌面或认证界面时禁止开始录音；已在录音则立即取消、清空音频缓冲且不显示正文反馈。
9. 发送文本 AI 前将正文与用户指令分通道封装；正文中的提示词样式文字只作数据，不能改变目标主机、上传范围、操作范围或保护规则。

### 15.1 交付兼容性测试矩阵

每个平台至少覆盖以下目标；“通过”可以是直接插入成功，也可以是按设计明确降级到剪贴板，但不能静默丢失或误投：

| 类别 | macOS 基线 | Windows 基线 | 重点 |
|---|---|---|---|
| 系统文本框 | TextEdit、Notes | Notepad | 普通插入、选区替换、撤销提示 |
| 办公写作 | Microsoft Word、Pages | Microsoft Word | 多段正文、选区替换、中文输入法组合态、不可确认时剪贴板回退 |
| 浏览器 | Chrome / Safari 输入框、`contenteditable` | Chrome / Edge 输入框、`contenteditable` | 浏览器元素重建后的目标复核 |
| Electron | VS Code | VS Code | Accessibility / UIA 能力与剪贴板回退 |
| 中文输入法 | 系统拼音输入中、候选框关闭后 | 微软拼音输入中、候选框关闭后 | 不打断未提交组合文本；不确定时回退 |
| 无焦点 | 桌面、菜单、只读网页 | 桌面、任务栏、只读网页 | 自动剪贴板、反馈条、有限撤销 |
| 目标切换 | 转写中切 App / 窗口 / 输入框 | 同 | 新焦点零误插入 |
| 安全输入 | 密码框、系统认证弹窗 | 密码框、UAC / 系统认证 | 拒绝录音或丢弃晚识别结果；不插入、不复制、不展示全文 |
| 多屏与全屏 | 主副屏、全屏 App、Dock 避让 | 主副屏、全屏 App、任务栏避让 | 悬浮条可见且不抢焦点 |

每次 Release 在 `tests/manual/` 保存版本、系统、应用版本、结果和已知限制；不能用“Mac / Win 各测一遍”代替矩阵。

可靠性统计每个平台至少执行 100 次 5 秒内短句交付，覆盖直接插入、无焦点、目标切换和取消；总成功率至少 99%，其中误投、安全输入外泄和取消后落字必须为 0。

### 15.2 自动化与发布验收

| 层级 | 必测内容 |
|---|---|
| `luozi-core` 单测 | 两条状态线全部合法 / 非法转换、取消与晚到结果、EngineRouter、云端授权、错误归一化、剪贴板恢复条件 |
| 编辑核心单测 | 范围解析、段落定位、最近一次落字有效期、保护片段、风险升级、正文版本冲突、20 步撤销 / 重做、标注随文本变更、退出前保存刷盘 |

| 模型测试 | 清单解析、空间不足、断点文件、SHA256 失败、原子安装、自选模型校验 |
| 配置测试 | 新配置、旧 schema 迁移、损坏配置保留与恢复、凭据引用不含明文 |
| 工作台交互测试 | 两个快捷键、粘贴不自动上传、首次 AI 配置后续接原指令、局部修改、全文高风险预览、语音 / 键盘撤销与重做、复制不带标注 |
| 平台集成测试 | 能自动化的热键注册 / 冲突 / 重启复核、目标变化、锁屏取消、剪贴板序列号、系统材质降级和临时文件清理；真实 Pressed / Released 与其余项目进 §15.1 手工矩阵 |
| 性能测试 | 托盘空闲、工作台空闲、模型按需加载 / 释放、100 次短句、30 次 AI 修改后的资源回落 |
| 发布检查 | Rust fmt / lint / test、前端 lint / test / build、双端安装包、SHA256、敏感信息扫描、实机冒烟 |

发布阻断条件：

- 出现任何新焦点误插入、安全输入结果外泄或取消后晚到落字。
- Key、音频、转写全文进入日志、崩溃包或仓库。
- 推荐模型哈希不匹配仍被加载。
- 任一正式支持平台无法完成安装、热键录音、至少一个引擎转写和剪贴板回退。
- 文本 AI 越过选区 / 当前段、静默改变保护片段，或 AI 失败导致原文丢失。
- 草稿正文中的提示词样式文字能扩大上传 / 改写范围，或更换目标主机而不重新授权。
- 工作台复制 / 导出带出内部颜色标记、置信度或不可见控制字符。
- 连续完成 30 次录音、转写、交付和取消后，临时音频仍有残留，或空闲 CPU / 内存持续增长且 5 分钟内不回落到稳定区间。

### 18.1 外部能力依据与复核点

以下能力在拆实现计划和每次发版前复核，避免把会变化的厂商事实写成永久承诺：

- Tauri 2 全局快捷键的 `Pressed` / `Released` 事件、注册状态与冲突行为：[插件指南](https://v2.tauri.app/plugin/global-shortcut/)、[API 参考](https://v2.tauri.app/reference/javascript/global-shortcut/)；真实按住 / 松开仍需双端实机验证。
- macOS 系统快捷键可能占用候选组合；例如 `⌥⌘Space` 已用于 Finder 搜索：[Apple Spotlight 快捷键](https://support.apple.com/en-eg/guide/mac-help/mh26783/mac)。Windows 候选键遵循系统快捷键保留规则并用实机确认：[Microsoft Keyboard interaction](https://learn.microsoft.com/en-us/windows/win32/uxguide/inter-keyboard)。
- 单键 / 组合键在不同键盘与系统设置下可用性不同，可参考同类产品公开的支持与不支持清单建立测试样本：[Wispr Flow shortcuts](https://docs.wisprflow.ai/articles/2612050838-supported-unsupported-keyboard-hotkey-shortcuts)；只参考兼容性问题，不复制其默认键。
- Apple Liquid Glass 的层级与使用边界：[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)、[Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/liquid-glass)；实现时遵守“玻璃用于控制与导航，不铺在正文内容层”。
- Apple Speech 是否支持本机识别需检查 `supportsOnDeviceRecognition`：[Apple 文档](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition)。
- Windows Speech 的联网、语言与包身份限制：[Microsoft Speech Recognition](https://learn.microsoft.com/en-us/windows/apps/develop/input/speech-recognition)。
- Groq 转写端点、模型、文件与最低计费时长：[Groq Speech to Text](https://console.groq.com/docs/speech-to-text)；数据留存与 ZDR：[Groq Your Data](https://console.groq.com/docs/your-data)。
- 硅基流动当前 ASR 模型与文件限制：[SiliconFlow Audio Transcriptions](https://docs.siliconflow.cn/cn/api-reference/audio/create-audio-transcriptions)。
- 智谱当前模型、字段与 30 秒限制：[智谱语音转文本](https://docs.bigmodel.cn/api-reference/%E6%A8%A1%E5%9E%8B-api/%E8%AF%AD%E9%9F%B3%E8%BD%AC%E6%96%87%E6%9C%AC)。
- 市面能力参考只用于验证交互规律：[Typeless](https://www.typeless.com/)、[Superwhisper](https://superwhisper.com/docs/get-started/introduction)、[Wispr Flow Command Mode](https://docs.wisprflow.ai/articles/4816967992-how-to-use-command-mode)；不得复制其 UI、图标和文案。
