# Luozi 核心体验、AI 服务与单键输入改造设计

**日期：** 2026-07-29

**状态：** 已确认，待实施计划

**范围：** Mac-first；AI 服务绑定、识别与整理链路、设置布局、可更换单键快捷键、草稿问题标记和轻量性能边界

## 1. 结论

Luozi 继续定位为菜单栏优先的系统级语音输入工具，核心体验只有一句话：

> 在任意输入框按住自己设置的按键，说话，松开，得到准确、自然、可直接使用的文字。

围绕这条主链路，产品必须同时做到：

1. **简单：** 普通用户不需要理解 ASR、Base URL、协议和凭证引用。
2. **灵活：** 识别服务、文字整理服务、模型、输入模式和快捷键均可更换。
3. **兼容：** 支持内置厂商、OpenAI 兼容服务、本地模型和安全降级。
4. **强大：** 能处理口头修正、语气词、标点、换行、列表、专有词和语音修改。
5. **轻量：** 常驻状态不持续运行模型、隐藏页面、动画、轮询或网络探活。

本设计不通过堆叠功能实现“强大”。主界面保持克制，高级能力按需展开。

本文是覆盖完整体验闭环的总设计，不对应一次大规模实现。后续必须按第 14 节拆成可独立验收的计划，禁止用一份超大计划同时改完所有模块。

## 2. 与既有设计的关系

### 2.1 继续有效

`2026-07-28-experience-redesign-design.md` 中以下决策继续有效：

- 菜单栏常驻，不以语音草稿工作台作为启动首页。
- HUD 只反馈聆听、处理、成功、失败和恢复状态。
- 语音草稿是长文和修改场景，不是日常落字的前置步骤。
- 视觉继续采用克制的「珍珠玻璃 + 呼吸泡 + 轨道声场」。
- 输入目标变化时不向新焦点误投；不可写时降级到剪贴板。
- 密码框、安全输入和晚到结果继续遵守现有安全边界。
- Key 只保存在系统钥匙串，不进入配置文件、日志或 Git。

### 2.2 本设计覆盖的旧决策

若与 2026-07-28 规格冲突，以本文为准：

- AI 服务不再全部隐藏到“高级”，而是成为独立、面向普通用户的设置入口。
- Key 不再通过系统脚本弹窗输入，改为设置页内的完整连接流程。
- 云端授权不再拆成多个孤立按钮，改为在“测试并连接”时完成明确告知和一次确认。
- 普通语音输入正式支持可选的 AI 轻量整理，不再只插入原始 ASR 结果。
- “自动”不再固定本地优先，而是按用户偏好、可用连接和实测质量路由。
- 快捷键录制、单键设置和 Mac 原生单键适配进入正式范围。
- `Fn` 不作为唯一承诺；所有实际可用的单键与组合键均可录制和替换。
- ASR、文本 AI、设置和快捷键不再分散追加功能，而是按一条完整体验链路重构。

现有 `2026-07-28-r1-experience-redesign.md` 不能直接作为本设计的实施计划。后续需基于本文重新拆解，并先处理当前工作树基线。

## 3. 产品结构

Luozi 只保留四个主要界面。

| 界面 | 生命周期 | 主要职责 | 不承担 |
|---|---|---|---|
| 菜单栏浮层 | 常驻入口、按需显示 | 就绪状态、主快捷键、开始输入、打开草稿和设置 | 不承载完整配置 |
| 临时 HUD | 会话期间显示 | 聆听、识别、整理、写入、失败和恢复反馈 | 不显示长文和复杂按钮 |
| 语音草稿工作台 | 按需创建 | 长文、问题标记、语音修改、AI 润色、粘贴文字美化 | 不作为启动首页 |
| 设置 | 按需创建 | 通用、语音输入、AI 服务、快捷键、权限和高级配置 | 不展示概念海报 |

正常启动只显示菜单栏图标。设置、草稿等窗口关闭后销毁可释放的 WebView 资源，需要时再恢复。

## 4. 日常落字与工作模式

### 4.1 主流程

```text
当前输入框有光标
  → 按住用户设置的主快捷键
  → 100 ms 内显示聆听 HUD
  → 说话
  → 松开快捷键
  → 音频预处理
  → 语音识别
  → 词典和数字保护
  → 按模式进行整理
  → 校验原输入目标
      → 有效：原位写入
      → 失效或不可写：复制到剪贴板并提示
  → HUD 收口
```

### 4.2 三种用户模式

设置中只展示三个容易理解的模式：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| 快速落字 | ASR + 本地确定性格式处理，不等待文本 AI | 短消息、速度优先、网络不稳定 |
| 智能落字 | ASR + 词典保护 + 受约束的 AI 轻量整理 | 默认推荐，输出可直接发送 |
| 原文模式 | ASR + 最小标点处理，尽量保留原话 | 会议记录、专业内容、逐字材料 |

AI 整理不是基础转写的依赖。AI 不可用、超时或返回无效结果时，自动使用通过基础检查的 ASR 结果。

### 4.3 草稿工作台的三项能力

1. 在语音转写或简写文字基础上检查问题、纠错和继续编辑。
2. 使用模型进行润色、压缩、扩写、改语气和结构化。
3. 粘贴外部文字后进行美化，并可用语音继续修改。

草稿内支持选择一段文字后说修改要求；高风险改动继续先预览再确认。

## 5. AI 服务绑定

### 5.1 用户心智

设置增加一级入口“AI 服务”。普通用户只需要知道：

- 我连接了哪些服务。
- 哪个服务负责语音识别。
- 哪个服务负责文字整理。
- 当前是否可用、速度大致如何。

设置中不出现 `credential_ref`、请求路径和协议枚举等内部概念。

### 5.2 添加服务流程

添加服务固定为三步。

#### 第一步：选择服务商

服务商卡片直接显示能力标签：

- `语音识别`
- `文字整理`
- `本地`
- `需要 Key`

首批目标包括：

| 服务 | 语音识别 | 文字整理 | 凭证说明 |
|---|---:|---:|---|
| Groq | 支持 | 支持 | 按实际服务能力复用或分开保存 |
| 千问 / DashScope | 支持 | 支持 | 默认带出中国区兼容地址 |
| 豆包 / 火山引擎 | 支持 | 支持 | 语音和方舟文本凭证按实际要求分开引导 |
| 小米 MiMo | 按兼容测试开放 | 支持 | 不通过兼容测试时不展示虚假可用状态 |
| OpenAI | 支持 | 支持 | 使用官方兼容协议 |
| DeepSeek | 不支持 | 支持 | 只用于文字整理 |
| OpenAI 兼容服务 | 按协议检测 | 支持 | 高级区填写地址和模型 |
| 本地 Whisper | 支持 | 不支持 | 不需要 Key |

厂商能力由兼容测试和版本内置清单共同决定。未通过验证的能力显示“暂不可用”，不能只因名称存在就允许选择。

#### 第二步：填写凭证

内置服务默认只显示：

- API Key 或厂商实际凭证。
- 推荐模型。
- “怎么获取 Key”。
- 折叠的“高级设置”。

内置服务自动填写 Base URL 和推荐模型。高级设置只在以下场景展开：

- 自定义兼容服务。
- 用户需要指定模型。
- 厂商使用非标准地址。
- 诊断连接问题。

“怎么获取 Key”提供：

1. 官方控制台入口。
2. 创建 Key 的三到四步说明。
3. 官方接口文档。
4. 该服务是否收费、需要开通模型或创建 Endpoint 的醒目提醒。

Luozi 不收集厂商账号密码，也不把厂商登录页嵌入应用。

本地 Whisper 不显示 Key 教程，改为模型下载、文件体积、来源、许可证、预计内存占用和卸载方法。

#### 第三步：测试并连接

页面只保留一个主要动作：`测试并连接`。

连接测试分别验证：

- Key 或凭证格式。
- 认证是否有效。
- 模型是否存在。
- 服务是否支持目标能力。
- 网络连通性。
- 本次最小请求的实际延迟。

文字整理测试只发送固定的合成测试句；语音识别测试只发送随应用提供的短测试音频，不发送用户草稿或历史内容。单次结果显示“本次延迟”，P50 / P95 只来自版本基准或多次实测，不能用一次请求伪装成统计值。

测试结果明确区分：

- Key 无效。
- 模型不存在。
- 服务未开通或额度不足。
- 请求限流。
- 网络或 DNS 不可用。
- 接口协议不兼容。
- 测试成功。

不得把这些错误统一显示为“配置失败”。

### 5.3 隐私确认与 Key 管理

隐私说明与连接动作放在同一页面：

> 启用后，语音识别会向所选服务发送本次录音；文字整理会发送待处理文字。Luozi 不经过官方中转，Key 只保存在本机钥匙串。

用户确认后，点击一次“测试并连接”即可保存凭证并启用所选能力，不再要求随后单独点击一个“同意上传”按钮。

安全要求：

- Key 明文只存在于当前输入控件和写入钥匙串的短生命周期内存中。
- 保存后只显示掩码、连接状态和更换入口。
- 日志、诊断信息、错误消息和前端快照不得包含 Key。
- 删除连接时同时删除对应钥匙串项；删除前明确确认影响的能力。
- 同一凭证只有在厂商实际允许时才跨能力复用。

### 5.4 服务路由

用户可以分别选择：

```text
语音识别：Groq
文字整理：DeepSeek
```

也可以让同一连接承担两种能力。更换当前服务不删除旧连接。

“自动推荐”只在满足以下条件时选择一个服务：

1. 连接测试成功。
2. 能力与协议匹配。
3. 未处于已知限流或不可用状态。
4. 在基准测试中达到当前版本的质量门槛。

不做后台持续探活。状态在用户测试连接、实际请求或打开 AI 服务页时刷新。

## 6. 识别与 AI 整理链路

### 6.1 音频预处理

录音链路只做低成本处理：

- 转换为识别所需采样率和声道。
- 去除明显的头尾静音。
- 限幅和基础音量归一。
- 检测无有效语音。

首版不引入常驻深度降噪模型。复杂降噪只有在数据证明收益明显且性能可接受时才单独设计。

### 6.2 ASR 路由

路由遵守用户明确选择：

- 用户固定本地：只走本地，不静默上传。
- 用户固定云端：走指定连接；失败后只有用户开启“允许本地回退”才回退。
- 自动推荐：网络可用且已有通过质量门槛的连接时优先使用该连接；否则使用已就绪的本地模型。

自动模式不以“本地一定更好”或“云端一定更好”为假设，依据版本基准、连接状态和用户隐私偏好决定。

### 6.3 确定性保护层

ASR 结果先经过不调用大模型的保护层：

- 空白、重复标点和基础中英文间距规范。
- 数字、日期、时间、金额、URL 和邮箱识别。
- 个人词典匹配。
- 已知产品名、姓名、缩写和技术词的保护。
- 过短、全噪音或明显无效结果拦截。

个人词典保存在本机。首期支持用户手动添加“常说形式 → 正确写法”，不在后台自动上传或训练。

### 6.4 AI 轻量整理

智能落字模式允许：

- 删除“嗯、啊、那个”等无意义口头语。
- 处理“下午两点，不对，三点”这类即时修正。
- 修复明显重复和口语断裂。
- 增加标点、自然换行、编号和列表。
- 在不改变意思的前提下让文字可直接阅读。

禁止：

- 添加用户未说过的事实。
- 随意修改数字、日期、金额、链接、代码标识符和受保护词。
- 把普通转写改写成完全不同的文风。
- 返回 Markdown 围栏、解释文字或多候选答案。

AI 请求需携带受保护片段清单，并要求返回最终纯文字和可选的疑似问题位置。返回结果必须经过结构、长度、受保护片段和风险检查；检查失败即使用 ASR 结果。

### 6.5 延迟预算与降级

针对不超过 10 秒的短语音，目标为：

| 阶段 | 目标 |
|---|---:|
| 按键到 HUD 聆听反馈 | ≤ 100 ms |
| 松开到最终写入 P50 | ≤ 1.5 s |
| 松开到最终写入 P95 | ≤ 3 s |
| AI 整理交互预算 | 约 1.2 s |

AI 超出交互预算时停止等待，使用基础转写。云端 ASR 超时且本地已就绪时允许按路由规则回退；任何失败都不得改变原输入框内容。

长语音按音频长度单独统计，不使用短语音目标掩盖真实性能。

### 6.6 疑似问题与颜色

丰富标记只在 Luozi 草稿工作台中显示：

- 红色波浪线：疑似识别错误，需要人工确认。
- 琥珀色底纹：AI 相对原始转写做了明显修改。
- 蓝色边界：当前语音修改的作用范围。

疑似问题只能来自可解释信号，例如服务返回的置信度、词典冲突、受保护片段变化或明显格式异常。不得仅凭模型主观判断大面积标红。

第三方 App 只接收干净纯文字，因为无法可靠控制外部编辑器的富文本颜色。HUD 可以提示“发现 2 处需检查”，并提供打开本次结果到草稿工作台的入口。

## 7. 快捷键系统

### 7.1 可配置动作

设置中提供录制式快捷键：

| 动作 | 默认交互 | 是否可更换 |
|---|---|---:|
| 语音输入 | 按住说话，松开结束 | 是 |
| 语音修改 | 独立按键，或同键“双击后按住” | 是 |
| 取消当前操作 | `Escape` | 是 |

高级选项允许把主输入改成“按一下开始，再按一下结束”，默认仍为按住说话。

### 7.2 单键兼容策略

快捷键管理分为两层：

1. 通用全局快捷键层：处理标准功能键和组合键。
2. Mac 原生单键适配层：在能力探测通过后处理 `Fn`、`Caps Lock` 等官方通用快捷键层无法可靠表达的按键。

用户目标是“单键操作”，不是绑定某一个固定键。首次引导让用户直接按下想使用的按键，并现场完成注册测试。

Mac 原生适配先做边界明确的兼容性 Spike，验证事件完整性、按下与松开、系统冲突、权限和资源占用。某类按键未通过 Spike 时不进入正式选项，改用其他已验证单键，不把实验性监听包装成可用功能。

规则：

- `Fn`、`Caps Lock` 和功能键仅在设备实测可用时出现为推荐选项。
- 字母、数字、空格、回车和退格不能直接作为全局单键，以免破坏正常输入。
- 系统保留键、输入法切换键和已注册冲突键必须提示具体冲突。
- 保存采用原子切换：新快捷键注册成功后才注销旧值。
- 注册失败时保留旧快捷键和可用入口。
- 两个动作不能保存完全相同的按键和手势。
- HUD、菜单栏、引导和帮助始终读取实际注册值，不写死示意键。

在用户完成单键设置前，保留当前已验证组合键作为应急兜底；完成后日常界面只突出用户选择的快捷键。

### 7.3 权限与降级

若 Mac 原生单键监听需要额外系统权限：

- 首次选择该类按键时解释用途并引导授权。
- 用户拒绝后立即返回通用快捷键选择，不阻断基础功能。
- 监听只处理用户明确绑定的按键，不采集或记录其他键盘内容。

## 8. 设置与视觉布局

### 8.1 设置结构

左侧固定六项：

1. 通用
2. 语音输入
3. AI 服务
4. 快捷键
5. 隐私与权限
6. 高级与关于

普通设置不再按底层模块平铺。页面中每个区域最多一个主要按钮，状态、选择和危险操作必须有明确层级。

### 8.2 页面原则

- 使用桌面密度的分组列表，不使用移动端超大卡片。
- 不为每一行放一个问号；复杂说明使用行内副标题或统一帮助入口。
- AI 服务页的主动作是“添加服务”或“测试并连接”。
- 快捷键页的主动作是当前正在录制的按键区域。
- 权限页只显示用途、当前状态和打开系统设置。
- 暂不可用能力不占据普通设置首屏。

### 8.3 液态玻璃边界

玻璃效果用于：

- 菜单栏浮层。
- 临时 HUD。
- 设置侧栏。
- 模态连接和快捷键录制面板。

正文编辑区和设置内容区使用清晰的半实体表面。避免整窗透明、全屏薄荷色洗和大面积持续模糊。

所有玻璃表面必须适配：

- 深色模式。
- 降低透明度。
- 增强对比度。
- 减少动态效果。

设置窗口不得依赖固定宽度造成横向裁切。窄窗口下侧栏收窄或切换顶部导航，内容行改为上下布局。

## 9. 草稿工作台

工作台采用三段结构：

1. 顶部：标题、当前输入模式、撤销和必要状态。
2. 中间：正文编辑器、疑似问题标记和待确认修改。
3. 底部：主语音入口、润色入口和“说修改要求”入口。

主要交互仍以语音完成：

- 光标处继续说。
- 选中文字后说修改要求。
- 直接说“更简洁一点”“改成正式通知”“把这段列成三点”。
- 高风险改动先显示差异，低风险改动可直接应用并支持撤销。

按钮只负责发现和兜底，不要求用户为了完成一次修改连续点击多个控件。

## 10. 组件与职责边界

| 单元 | 职责 | 不负责 |
|---|---|---|
| `ProviderRegistry` | 内置服务、能力、默认地址、模型和教程元数据 | 不保存 Key |
| `ConnectionStore` | 连接状态、钥匙串引用、删除和迁移 | 不发起识别 |
| `ConnectionTester` | 认证、模型、能力和延迟测试 | 不修改当前路由 |
| `CapabilityRouter` | 选择语音识别与文字整理服务 | 不渲染设置 |
| `RecognitionPipeline` | 音频预处理、ASR、保护层和降级 | 不直接操作外部焦点 |
| `CleanupEngine` | 受约束的 AI 整理和结果校验 | 不保存用户全文 |
| `ShortcutManager` | 录制、冲突检测、原子注册和平台适配 | 不启动具体会话逻辑 |
| `DraftAnnotations` | 疑似问题、AI 差异和修改范围 | 不改变第三方富文本 |
| `SettingsShell` | 六个设置分区和状态展示 | 不直接访问钥匙串 |

这些单元通过明确的数据对象传递状态，避免继续把供应商、系统弹窗、路由和 UI 事件堆进单个 controller。

## 11. 错误与恢复

| 问题 | 用户结果 | 恢复 |
|---|---|---|
| Key 无效 | 连接不保存为可用 | 返回 Key 输入并保留非敏感字段 |
| 模型不存在 | 明确指出模型问题 | 重新获取或手动选择模型 |
| 云端限流 | 本次不修改原输入 | 允许本地回退或切换连接 |
| AI 整理超时 | 使用基础转写 | HUD 轻提示已使用原始结果 |
| 本地模型缺失 | 不静默上传 | 提供下载或已连接云端选择 |
| 快捷键冲突 | 新设置不生效 | 保留旧值并提示冲突来源 |
| 原输入目标变化 | 不向新焦点写入 | 结果进入剪贴板 |
| 草稿标记解析失败 | 正文仍可编辑 | 去掉标记，不丢失纯文字 |
| 设置或 HUD 前端异常 | 会话必须可收口 | controller 超时隐藏并保留结果恢复入口 |

最后一次录音可在内存中短暂保留用于即时重试，超过恢复窗口立即释放；默认不把原始音频长期落盘。

## 12. 轻量性能边界

### 12.1 常驻行为

- 常驻时只保留菜单栏控制器、快捷键监听和必要状态。
- 设置、草稿、帮助等窗口按需创建；关闭后停止计时器并释放可释放资源。
- HUD 隐藏后停止动画、能量事件和渲染循环。
- 权限轮询仅在权限页可见时运行。
- 不在后台持续检测 AI 服务。
- 未录音时不占用麦克风。

### 12.2 本地模型

- 本地模型按需加载。
- 默认闲置约两分钟后卸载；正在连续使用时避免反复加载。
- 设置中明确显示模型体积和“速度 / 准确率 / 内存”倾向。
- 自动推荐不能默认选择明显超出设备承受范围的模型。

### 12.3 性能目标

以项目指定的参考 Mac 实机测量：

- 五分钟空闲期间，Luozi 进程树 CPU 中位数低于 `0.5%`。
- 无录音、无本地模型加载时，进程树常驻内存目标不高于 `150 MB`。
- 空闲时无持续 GPU 动画和网络请求。
- 快捷键按下到聆听反馈不超过 `100 ms`。
- 隐藏窗口不得保留可观察到的前端轮询。

如果平台 WebView 基线导致内存目标不可达，实施报告必须列出各进程占用、不可控系统开销和最小可达值，不能静默放宽目标。

## 13. 质量与测试

### 13.1 固定语料

建立至少 100 条可重复测试样本，覆盖：

- 普通中文短句。
- 中英文混合。
- 姓名、产品名、缩写和开发术语。
- 数字、日期、金额、网址和邮箱。
- 用户说到一半自行纠正。
- 列表、长句和自然换行。
- 不同麦克风、轻度环境噪音和较小音量。

测试样本不得包含真实 Key、客户隐私和不应公开的工作材料。

### 13.2 指标

每个可推荐识别方案至少记录：

- 中文字符错误率。
- 英文词错误率。
- 数字与受保护词错误率。
- 无需人工修改率。
- P50 / P95 识别时间。
- P50 / P95 最终写入时间。
- 峰值 CPU、内存和模型加载时间。

“推荐”标签必须由版本内基准支持，不按供应商品牌或主观感觉决定。

### 13.3 自动与实机检查

自动检查包括：

- 连接配置迁移、钥匙串引用和敏感信息脱敏。
- 服务能力匹配、错误映射和路由降级。
- AI 结果对数字、受保护词和长度的校验。
- 快捷键冲突、原子切换和失败回滚。
- 会话取消、晚到结果和输入目标变化。
- 设置窄窗口布局和减少动态效果。
- `npm run build`。
- `cargo fmt --all --check`。
- `cargo clippy --workspace --all-targets -- -D warnings`。
- `cargo test --workspace`。

Mac 实机检查包括：

- 短按、按住、重复触发和按键冲突。
- Safari、Chrome、备忘录、微信、终端和常用 IDE。
- 本地、云端、离线、限流和 AI 超时。
- 麦克风、辅助功能和单键监听权限拒绝与恢复。
- 设置、草稿、HUD 关闭后的 CPU、内存和网络活动。

## 14. 实施切片

后续计划按以下顺序拆解，不能在一个切片里全量重写：

1. **基线与测量：** 固化当前可用链路、性能采样方法和识别测试集。
2. **AI 服务中心：** 页面内 Key、服务连接、教程、测试、能力路由和旧配置迁移。
3. **识别质量链路：** 保护层、智能整理、延迟预算、降级和基准报告。
4. **设置与工作台：** 六分区布局、响应式窗口、草稿标记和语音修改入口。
5. **快捷键系统：** 录制、冲突检测、原子切换、Mac 单键适配和引导。
6. **轻量收口：** 窗口生命周期、模型卸载、动画停止和性能验收。

当前工作树已有大量未提交改动，且与设置、供应商和会话 controller 重叠。实施计划开始前必须先确认这些改动的归属和基线；不得自动暂存、覆盖或丢弃。

## 15. 验收标准

1. 新用户三分钟内能够连接一个服务并完成第一次语音输入。
2. 内置服务普通流程只需选择厂商、粘贴 Key、测试并连接。
3. 所有已保存 Key 仅存在于系统钥匙串，日志和界面快照不含明文。
4. 语音识别与文字整理可使用同一服务或不同服务。
5. 智能落字失败时基础转写仍能完成，不丢失本次输入。
6. 短语音在良好网络下达到 P50 `≤ 1.5 s`、P95 `≤ 3 s` 的目标，未达到时有分阶段数据。
7. 数字、日期、金额、URL、代码标识符和个人词典内容不会被 AI 无依据修改。
8. 所有用户级快捷键均可录制、更换和恢复；单键在设备实测可用后才能保存。
9. 快捷键注册失败不会让现有可用快捷键失效。
10. 设置页在窄窗口不横向裁切，普通用户首屏不堆叠技术字段。
11. 草稿工作台能区分疑似错误、AI 明显修改和当前语音修改范围。
12. 第三方 App 只接收干净纯文字，富文本标记不污染外部内容。
13. 常驻状态达到 CPU、内存、动画、轮询和网络活动的轻量目标，或在报告中明确记录平台不可控差异。
14. 旧配置和钥匙串项完成兼容迁移，不要求用户无故重新填写全部 Key。

## 16. 明确非目标

- 不复刻 Cherry Studio、Wispr Flow、Typeless 或其他产品的品牌与界面。
- 不做账号体系、官方代理中转、套餐计费和云同步。
- 不在首期支持无限协议类型；优先内置服务和 OpenAI 兼容路径。
- 不允许任意字母、数字或空格成为破坏正常输入的全局单键。
- 不把疑似错误标记写入第三方富文本。
- 不为“智能”长期保存原始音频或全文。
- 不引入常驻深度降噪模型、持续屏幕读取或后台键盘采集。
- 不把历史扩展成多文档知识库。
- 不在当前脏工作树上直接展开跨模块重构。
